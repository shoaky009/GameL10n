# 使用、备份与续译

## 导入与翻译

点击“添加游戏”，选择包含游戏程序和资源的安装目录。左侧游戏列表用于切换项目；识别完成后，界面显示文本数量、适配能力和已知限制。译文范围包括对白、旁白、角色名和选项，不包含图片内文字。

游戏列表显示名称、状态和安装路径，可按名称或路径搜索。运行和排队中的项目自动置顶，暂停或结束后按最近更新时间排列；搜索仍会筛选置顶项目。搜索只改变列表，当前打开的项目和后台任务继续保留。多选操作仅针对当前列表中的已选项目。

项目顶部会显示正在进行的步骤，例如等待任务名额、匹配引擎、校验资源、加载文本或下载共享工具。下载时显示实际数据量；没有可计量总量的步骤显示活动指示，不估算百分比。切换到其他项目后，原任务仍在后台继续。

点击游戏项目只打开已有状态，不会自动开始常规识别或智能适配；新项目需要自行选择识别方式。已提取项目使用上一次成功结果，游戏更新后请点击“重新识别”。重新识别失败或取消时保留旧结果，已有译文仍可使用。

本次运行中会缓存近期打开的文本和校对界面，切换回来保留搜索、筛选及位置。程序重启后，或空闲文本缓存因内存上限而被释放后，首次打开会读取已保存内容；这不会重新提取或调用模型。旧版记录缺少引擎或启动信息、保存记录损坏或适配器版本不可用时，会提示主动处理，不会自动启动识别。生成和安装补丁仍执行完整性与版本检查。

选中项目后点击“移除”，或先点击“多选”勾选多个项目，再批量移除。默认保留项目文件，重新添加同一游戏目录可继续使用原译文和设置。勾选“同时删除对应项目数据文件夹”会永久删除确认框列出的项目数据，包括译文、补丁、日志、原文备份及安装记录；不会删除游戏安装目录，也不会卸载已经安装的汉化补丁。删除安装记录后无法通过该项目自动恢复原版。所选项目正在运行的任务会先暂停并保存进度；其他项目不受影响。

“常规识别”仅匹配现有适配器，不调用模型。未匹配时可点击“智能识别与适配”，由项目选择的分析 API 调查资源、使用现成工具或开发引擎解析与回填能力。已有开发进度可以继续；适配通过后先选择少量文本试译。功能、预算和限制见[智能适配](adapters/automatic-adaptation.md)。

在“识别与适配”中点击“总结”，可使用项目的分析 API 从日志和已有源码提炼同类引擎的经验，单次最多 100,000 Token。分析指引和可复用辅助源码保存在数据目录的 `extensions/engine-knowledge`，由所有项目共享；智能识别按候选引擎查找，核对版本与格式条件后使用。项目证据和经验库未变化时直接展示上次总结，不调用模型；没有新的可靠优化时不会生成条目。总结结论与消耗保存在项目的 `engine-review.json`，不改动译文或游戏补丁。可在“引擎与兼容游戏”的“全局引擎经验”中查看或停用条目，对下一次分析生效。辅助源码仍需在当前游戏的样本上检查，适配器仍须通过完整验收；主程序修改建议单独展示，不会自动修改程序。

“项目设置”的“翻译语言与术语”中，术语表每行填写 `原文=译文`。更改术语后，只会使受相关术语影响的译文缓存失效。分析选择单个 API，翻译可配置按顺序尝试的 API 链，见[模型接口配置](model-providers.md)。

侧栏分为游戏项目与全局管理。选择游戏后，右侧显示“识别与适配”“翻译与校对”“补丁与验证”和项目设置；“全局”中的“API 与任务默认值”、引擎与兼容游戏、程序设置供所有项目共用。在“API 与任务默认值”统一选择分析 API、翻译 API 链及适配预算和轮数，新项目直接跟随；项目内可以分别改为独立配置，或重新勾选“使用全局默认”。旧项目保留已有设置。切换到全局页面会保存当前项目设置；全局默认修改用于下一次任务，无需重启。

翻译时可以切换到其他游戏继续识别或翻译。设置、暂停按钮、进度和日志只对应当前游戏；切换不会取消后台任务。同一游戏同时执行一个任务，默认最多两个游戏并行翻译。常规识别、智能适配和翻译分别调度，智能适配同时运行一个游戏；相同服务商账号的 API 请求依次执行。可在“程序设置”调整并行翻译数量，重启后生效。

## 少量试译

识别游戏后进入“翻译与校对”，按脚本、文本类型、校对状态筛选，或搜索原文、译文、角色和位置；勾选要验证的文本，也可在“选择与批量操作”中选中本页或全部匹配文本。每页显示 80 条，翻页、切换筛选和重启都会保留选择，勾选“仅显示已选文本”可以复查。列表顺序是资源提取顺序，不代表剧情播放顺序，建议选择开场或可以从存档到达的片段。

点击“试译并生成补丁”后，只翻译选中的文本，其余文本保留原文，即使它们已有缓存译文也不会加入本次试译补丁。在“补丁与验证”点击“安装试译补丁”，按界面提示的启动方式进入游戏，对照字体、乱码、换行、角色名和选项显示。“查看本次文本”显示这份补丁实际使用的译文；补丁目录的 `translation-snapshot.json` 保存同一份文本快照。结构校验通过不代表已经验证游戏显示。

试译中断后，点击“继续上次翻译”可继续原选区，也可改为全量翻译。已完成的试译译文继续复用，不需要重新付费翻译。试译和全量补丁分开保存，安装仍使用原有 `.bak` 备份与恢复机制。

SFA16 / AOS v2 的中文启动程序统一使用 CP936。保留的日文会以该编码写入；不支持的符号“・”和“♪”分别显示为“·”和“～”，受影响条数会记录在补丁警告中。原文快照保持不变。

## 编辑与校对

“翻译所选”仅处理勾选文本，“开始全量翻译”处理全部文本，两者都会复用已有有效译文，只生成并保存译文；“试译并生成补丁”连续完成所选文本的翻译和补丁生成。普通翻译期间可以编辑已有文本，后台返回的模型译文不会覆盖手工修改。

需要批量重做已有译文时，先筛选并勾选文本，也可用“全选匹配文本”，再点击“重新翻译所选”。确认后会重新请求当前翻译 API，包括所选的已编辑、已校对文本；新结果通过格式检查后才替换，并标为待校对，失败文本保留旧译文，未选文本不受影响。重译期间暂停本项目的编辑和校对；中断或重启后点击“继续上次翻译”并选择“继续原选区”，只处理本次未完成的文本。再次点击“重新翻译所选”则开始一轮新的重译。重译完成后需要重新生成补丁，已有补丁不会自动改变。

右侧编辑区显示资源路径、适配器提供的位置、原文和相邻上下文。文本序号是提取顺序，不等同于源文件行号；脚本可能位于资源包内部。输入译文后稍停即保存，切换项目和关闭窗口前也会保存。格式问题允许作为草稿保留，但不能确认校对或用于补丁。原文、上下文或目标语言变化后，旧校对记录不自动应用。

“确认校对，下一条”单独记录人工确认状态；继续编辑会取消该条确认，也可直接标为待校对。批量操作可确认所选的有效译文，未翻译和格式有问题的文本会跳过；确认前仍需人工检查含义和表达。“重新翻译并对比”生成候选，采用后才替换当前译文；选择“稍后处理”会保留候选，重启后可继续对比。与当前文本匹配的术语可点击插入。

“生成补丁”可使用所有已有译文或所选文本，并可限制为已确认校对的译文。未选入和未翻译的文本保留原文。补丁保留生成时的内容；编辑其中的译文后会提示重新生成，编辑范围外的文本不会影响这份补丁。游戏内验证结果由用户单独记录，不等同于结构校验。

快捷键：Ctrl+K 搜索，Ctrl+S 保存，Ctrl+Enter 确认校对并进入下一条，Alt+↑/↓ 切换文本。

## 安装与恢复

“补丁与验证”显示产物目录、启动方式和验证状态。安装器只写入补丁清单声明的文件，替换前备份原文件为 `.bak`；已有同名备份时，使用带时间和唯一标识的 `.bak` 文件名，保留旧备份。目标文件版本与制作补丁时不符时停止安装。

点击“安装试译补丁”或“安装汉化补丁”会自动写入导入时选择的游戏目录，无需手动复制。只读原文件在备份和校验完成后解除只读限制以便替换，恢复原版时恢复其只读属性。安装结果或失败原因直接显示在补丁页；安装或恢复前请关闭游戏和汉化启动器，程序检测到它们仍在运行时会提示关闭。

安装或恢复因文件占用等原因中断后，关闭游戏并再次点击同一按钮即可继续。程序根据安装记录与实际文件校验结果恢复，不需要删除记录、重新翻译或另建备份；无法确认的外部修改会保留并提示冲突。

安装记录保存在项目数据目录的 `installation.json`，随项目数据一起迁移。游戏目录只保留汉化运行文件、必要许可文件和替换原文件时的 `.bak`；游戏运行不依赖项目数据。旧版游戏目录里的 `.avg-translator` 安装记录会在下次安装、恢复或修复时迁入项目，确认保存后移除旧记录、锁文件及空目录。自动恢复原版需要保留项目数据。

“恢复原版”恢复原文件并移除本工具新增的补丁文件。安装后被游戏更新或其他程序修改的文件不会被强行覆盖，冲突会显示在日志中。

结构校验通过说明资源符合适配器的结构要求。游戏显示、排版、分支和存档兼容性需要实际运行验证，界面单独显示此状态。

## 缓存与续译

已完成译文按原文、上下文、文本类型、目标语言、风格和相关术语匹配。近似原文不直接复用。暂停或重新打开程序后，打开项目并开始翻译即可继续；已安装补丁的游戏使用保存的原文快照，重新识别时从经过校验的原文件备份读取原文。

每批模型响应先临时保存，再提交译文缓存；成功提交并记录进度后删除本批请求和响应，只保留异常及未完成记录。模型明确拒绝处理内容时，自动将同一批文本交给翻译 API 链中的下一项；续译时跳过已拒绝的 API，也可向链中追加配置继续尝试。网络、429、超时和返回格式错误不触发切换，而是对当前 API 每隔 10 秒重试一次，最多重试 5 次（加上首次请求共 6 次）。

全量翻译中，重试耗尽或整条 API 链拒绝的批次会标记为“翻译失败”，继续后续批次。模型遗漏或译文格式不合格时，仅对应文本失败，同批有效译文照常保存。结束时显示成功与失败数量；可在“翻译与校对”的状态筛选中选择“翻译失败”，点击文本查看原因。失败状态保存在原有 `translation-errors.json` 中，重新打开仍可查看；再次继续全量翻译会复用成功译文，只处理未完成文本。未授权重发的未知请求保持未发送并标记失败，其他文本仍可继续。

试译、所选文本重新翻译和单条候选译文仍在错误时停止，避免误认为选中的验证内容已经成功。用户取消、原文快照损坏、文件保存失败等任务级异常仍停止流程。等待重试期间可以手动暂停。全量任务有失败时不会自动生成完整汉化补丁；需要时可主动用已有有效译文生成补丁，其余保留原文。

数据默认保存在 `%LOCALAPPDATA%\AvgTranslator`，包括任务、原文快照、译文、补丁、扩展和兼容记录。在“程序设置”点击“更换保存位置”，选择“迁移并切换”或“仅切换”后立即生效，无需重启。迁移会复制并校验全部数据，保留原目录；仅切换则直接加载新目录已有的数据。切换前会暂停任务并保存进度，之后可继续。环境变量与旧版数据升级方式见[数据目录与迁移](data-storage.md)。原文快照和模型响应可能包含游戏文本。

## 汉化产物与适配器

安装后的游戏使用汉化资源和必要的中文启动程序，不需要本工具、适配器或模型服务。引擎／模板适配能力保留在制作工具中，用于制作其他游戏的补丁或处理资源更新。临时开发目录不属于玩家需要的汉化产物。

## 验证发布包

在全局引擎库选择外置引擎的“版本”，点击“验证发布包…”，选择一个已完成提取且当前空闲的同引擎游戏项目。程序使用该项目保存的原文快照和提取记录，从临时位置加载发布包，比较文本数量、ID、原文、定位及缓存字段，并执行原文往返、中文回填和局部试译检查。不会调用 LLM、安装补丁或切换项目固定版本。

验证过程中显示当前阶段，可取消。需要预留复制包和资源、生成测试输出的磁盘空间；本次临时文件在结束时移除。每个项目仅保存一份最新的 `package-verification.json`，包含成功、失败或取消状态，以及包、原文和提取基线指纹、工具链版本、验收规则版本和诊断。资源或版本变化后需要重新验证，旧报告不能作为当前版本通过的依据。

缺少原文快照或已有提取记录时不会自动重新解析、生成基线。换目录验收能发现常见的相对路径和缺失依赖问题，并提示发现的已知开发目录路径引用，但不是文件访问隔离；未访问的分支和隐藏绝对路径依赖仍可能遗漏。此操作不运行游戏，启动、字体和界面显示需另行实际验证。
