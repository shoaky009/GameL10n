# 消耗指标

左侧“消耗指标”展示识别与适配、智能适配、修复、扩展覆盖和经验总结的执行消耗。每次启动或继续独立计量，保存当时的软件版本、构建 Git hash，以及实际调用的模型配置。

## 筛选与对比

日期、版本、模型配置、游戏、任务类型、执行方式和状态可以组合筛选。模型配置按“配置名称 / 模型 ID / 推理强度”区分；同一模型在不同配置或不同推理强度下分别统计。未显式设置推理强度时显示“默认”。这些信息随运行保存，之后修改配置不会改变旧记录。旧记录缺少的信息显示“未记录配置”和“未记录强度”，不从当前配置补录。日期按系统时区显示和筛选，自定义日期包含开始与结束当天。

“分组趋势”按日期、软件版本、模型配置、任务类型、游戏、执行方式或状态分组。Token 用量以三条折线同时展示：蓝色为输入、橙色为输出、紫色为缓存输入，并用圆形、方形和菱形标记区分。三条线使用相同刻度；悬停或点击数据点可查看精确数值，点击后可用左右方向键选择。长名称省略显示，悬停名称可查看完整内容。未知计数不连线，部分计数以空心标记和“≥”表示。

未缓存输入、缓存命中率、耗时和请求次数使用柱条展示。除缓存命中率外，指标可切换合计与单次运行平均值。日期按时间先后排列；“执行记录”展示每次运行的配置与计数。全部操作直接在界面完成。

新运行、续接和复用结果分别标记。比较版本或模型时，可限定同一游戏和任务类型，并切换到单次运行平均值，减少任务数量及已有成果复用的影响。

## 计量口径

- 输入已包含缓存输入；总 Token 为输入与输出之和。缓存命中率为有效缓存计数请求的缓存输入总量除以输入总量，不平均各请求的百分比。
- API 请求次数包括失败和重试。失败响应返回的有效用量计入一次，结果解析失败或输出截断不会使这些用量消失。服务商未返回完整用量时不使用预算估算值填充指标；“未知”表示没有有效计数，“≥”表示仅累计已知部分，页面同时展示用量与缓存计数的覆盖请求数。
- 未缓存输入仅针对有有效缓存计数的请求计算。缓存计数缺失不能视为缓存未命中。
- 总耗时为本次任务实际经过的时间，包含准备、本地处理、API 和等待。API 耗时包含网络和服务端处理；等待耗时包含账户请求排队和限流重试等待；本地及其他耗时为其余时间。续接间隔不计入执行耗时。
- 每次运行只计新发生的 API 消耗，续接不会再次累计旧会话用量。读取已有总结等复用操作不重复计入原生成成本。金额取决于实际计费规则，页面展示 Token 与耗时，不换算费用。

## 保存

指标以小型 JSONL 记录追加到数据目录的 `metrics/runs-YYYYMM.jsonl`，按运行开始的 UTC 月份分文件。运行期间保存在内存；有进度更新时最多每分钟追加一次快照，结束时追加终态。相同运行 ID 取最后一条快照，不引入数据库、事务或每轮强制刷盘。

异常退出可能丢失最后一次保存之后的计数；未结束的已保存记录显示为中断，并保留已记录耗时。读取时跳过损坏或未写完的行，并显示无法读取的行数；指标不参与任务结果的一致性判断。

指标独立于项目详细日志和开发资料，清理这些文件不会删除指标。迁移数据目录时随数据复制。记录不保存提示词、源码、任务结果摘要或密钥；旧任务未记录的版本与消耗不从当前配置推算补录。
