# 架构与模块边界

## 模块

| crate | 职责 | 工作边界 |
| --- | --- | --- |
| `gamel10n-translation` | TranslationUnit、翻译策略与执行、Provider、记忆、通用校验、文件持久化基础 | 不引用引擎、项目管理或桌面模块，可独立供未来服务端使用 |
| `gamel10n-engines` | 引擎探测、智能适配、扩展管理、资源验收、Python 和固定原生工具 | 不管理游戏库和界面状态 |
| `gamel10n-core` | 项目、任务、提取缓存、原文快照、流水线、补丁及安装编排 | 不引用 Slint、窗口类型或界面线程调度 |
| `gamel10n-desktop` | Slint 展示、输入、选择状态、系统主题和窗口集成 | 通过 Core 接口操作业务，不直接实现解析或缓存规则 |

依赖方向为 `Desktop → Core → Engines → Translation`，Core 同时直接使用 Translation。CLI 位于 Core package，直接调用同一套应用服务。后续服务端可只依赖 Translation；当前不实现服务端。

UI 与 Core 同进程，通过普通 Rust 接口和异步事件协作。更换 UI 框架只影响 desktop。Slint 的模型、弱引用和事件循环调度只在 desktop 内出现；Core 的测试和 CLI 不初始化 UI。

## 任务与查询

用户操作显式启动提取或其他任务。打开项目只读取项目元数据与已有结果，不探测资源，不调用模型。项目列表只读摘要索引；文本首次加载后复用内存中的已提交提取结果，按页返回，搜索不重新解析游戏。

同一项目同时只有一个资源修改任务，不同项目可并行。任务归 Core 管理；切换页面不取消任务。Core 发出结构化任务事件，UI 映射为用户文案并更新底部日志。事件通道有界，界面落后不阻塞任务；需要时从任务快照重新同步。

## Rust、Python 与原生工具

Rust 管理智能适配的模型会话、工具调度、Token 预算、状态与独立验收。Python 用于模型生成的解析脚本和已有 Python 库。两者不各自维护一套项目任务状态。

已验证的脚本解析由 VNTextPatch NativeAOT EXE 执行，Rust 和 Python 沿用 UTF-8 JSON CLI v1。无需外置 .NET 运行时，不通过 CLR FFI 加载 DLL。C# 源码只保留在固定工具及格式参考中；重建 AOT 工具需要开发机的 .NET SDK，不进入桌面依赖。

子进程使用明确的可执行文件和参数，不拼接 shell 命令；隐藏控制台，同时处理 stdin/stdout/stderr，提供超时、取消和输出大小限制。独立进程本身不构成安全沙箱。当前 Python 入口面向明确选取的受信任脚本，扩展发布验收和权限管理仍需完整迁入。

## 持久化与兼容

继续使用本地 JSON 和文件系统，不新增数据库、消息队列或本地 HTTP 服务。项目路径身份、文本 ID 和译文指纹属于数据契约；格式变化必须单独验证，不能随 Rust 序列化库的默认行为改变。

已有 v2 项目和 v1 项目索引可读取，未识别字段在模型中保留。原有译文、校对、API 配置、引擎经验和安装记录不由当前入口改写。完整缓存指纹、受保护密钥及旧会话兼容在接入相应模块时验证。当前文件和能力边界见[数据说明](data-storage.md)。

Python 扩展沿用 CLI v1 方向，包管理和运行组件逐步接入。旧 C# DLL 扩展不能在 Rust 中直接执行；需要迁移到 Python 或独立原生工具并重新验收，不原地修改旧发布包的哈希和版本。

## 实施顺序

1. 工程边界、项目与分页查询、Python/NativeAOT 工具执行、脚本提取及回填。
2. Translation Provider、缓存指纹兼容、断点续译和校对数据。
3. 常规引擎发现、Python 包管理、运行组件和智能适配会话与工具链。
4. 补丁安装与恢复、完整 Slint 交互、发行与真实资源回归。

每个阶段以可执行的业务链路验收。当前实现范围由[开发文档](development.md)单独列出，不以目标说明替代实际功能。
