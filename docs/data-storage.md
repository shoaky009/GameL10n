# 数据目录与迁移

## 保存位置

默认目录为 `%LOCALAPPDATA%\GameL10n`。在“全局 → 程序设置 → 更换保存位置”中选择操作，完成后立即生效：

- **迁移并切换**：复制当前数据并校验后加载新目录，保留原目录。目标须为空或已有相同副本；不同内容会停止迁移。失败后仍使用原目录，可选择相同目标继续。
- **仅切换**：直接加载目标目录，不复制当前数据。空目录显示为空游戏库。

切换前暂停任务并保存状态。来源和目标不能相同、互相包含或与游戏目录重叠。

位置设置保存在 `%LOCALAPPDATA%\GameL10n\location.json`。`GAMEL10N_DATA` 环境变量优先，其次为兼容变量 `AVG_TRANSLATOR_DATA`；环境变量启动时，界面切换只影响本次运行。新目录没有设置或数据时，也可读取 `%LOCALAPPDATA%\AvgTranslator` 的既有位置和数据。

## 目录

```text
<数据目录>/
  settings.json                全局 API、密钥、默认值与并发限制
  games/index.json             游戏列表摘要
  games/<游戏 ID>/
    game.json                  项目路径、名称和独立设置
    installation.json          补丁安装、备份位置与恢复状态
    source.json                原文工作资源索引
    sources/<指纹>/            适配和补丁制作使用的原文资源
    extraction/<缓存键>/       提取清单与文本
    memory/00.json … ff.json    翻译记忆分片
    translation-edits.json     译文与校对快照
    translation-edits.jsonl    快照之后的增量记录
    translation-scope.json     翻译范围和完成状态
    trial-selection.json       已选文本 ID
    responses/                 未完成请求、异常与拒绝记录
    patches/                   补丁、报告、译文快照和运行反馈
    adaptation/current/        适配会话、源码、样本和工作资料
    logs/                      项目日志
    rust-task.json             最近任务状态与结果
    job.json、tasks/            翻译进度与成本汇总
  extensions/                  共享适配器、兼容记录、工具与引擎经验
```

游戏 ID 为规范化安装路径 SHA-256 的前 24 位；更改安装路径会产生不同 ID。迁移数据应保留原游戏路径。扩展目录详见[产物约定](adapters/artifacts.md)。

## 提交与恢复

项目元数据以 `game.json` 为准，列表读取 `games/index.json`。索引缺失时从项目元数据重建；`index-pending.json` 记录待同步项目，异常恢复只核对这些项目。索引损坏会报告错误，手动移走项目文件后可移除残留条目。

任务结果以 `rust-task.json` 为准，日志或索引更新失败不撤销已完成结果。重启后未结束的任务标记为中断，保留译文、选区和补丁。

配置、识别结果与任务状态采用原子替换。翻译记忆按缓存键前两位分片并保留恢复副本；提取缓存损坏时可由原文工作资源重新生成。

校对和重译先追加 `translation-edits.jsonl`，成功后更新内存，定期合并为 `translation-edits.json`。两份文件须一并保留；恢复忽略末尾未写完的记录，完整记录损坏则报错。

适配的 `session.json` 保存状态和历史位置，`session-history.jsonl` 保存消息。历史先落盘再提交快照，仅恢复已提交范围；旧历史按需查询。

翻译请求在提交前临时落盘，译文、进度及用量保存后移除。异常、拒绝及无法确认提交的响应保留，避免重试重复付费。API 密钥受 Windows 当前用户保护，换电脑或用户后需重新填写。

## 只读检查

在源码目录执行：

```powershell
cargo run -p gamel10n-core -- --data-directory 'D:\GameL10n Data' audit
```

`audit` 检查项目元数据和已有提取缓存，报告一致性与加载耗时，不调用解析器或模型。Debug 包提供同样的 CLI，其他入口见[资源静态验证](development.md#资源静态验证)。

## 保存与清理

完整替换文件不要求匹配生成补丁时的原文件哈希。首次安装时，将目标文件移动为游戏目录内的 `.bak`，记录实际哈希、时间和属性。目标缺失时直接写入，内容与补丁相同时跳过。

重复安装保留文件来源和原版备份信息，已安装文件被外部修改时报告冲突。覆盖包仍校验运行时依赖的原资源。

补丁新增文件在 `installation.json` 中记录 `originalExisted:false`；后续更新直接替换，不为旧补丁创建 `.bak`。未记录不存在的文件按原有文件处理，旧记录中明确为空的原始哈希继续表示新增文件。

“恢复原版”核对备份哈希后移动回原路径，再次校验成功才清除安装记录，保留已记录的时间和属性；补丁新增文件校验后删除，安装时新建且已为空的目录一并移除，原有目录和其他文件保留。中断后可继续；内容不符时保留文件并报错。`sources/` 是制作输入，不用于原版恢复；恢复依赖游戏目录的备份和 `installation.json`。

适配开发资料和日志保留供续作与诊断。单次调用的临时目录在结束时尝试删除，强制结束或文件占用时可能残留。

### 项目完工后清理

在“项目设置 → 清理项目文件”中查看各类别总大小并选择范围，默认全部勾选。清理期间仅占用当前项目。

| 类别 | 清理范围与影响 |
| --- | --- |
| 适配开发资料 | `adaptation/`、`validation/`；清理后无法续接原会话或基于已删除资料总结 |
| 原文工作资源 | `sources/`；再次制作补丁前需要重新识别 |
| 历史补丁 | 删除旧构建，保留当前补丁、译文快照与运行反馈；无法确定当前补丁时保留整个目录 |
| 过程日志与异常记录 | `logs/`、`responses/` |

保留项目设置、提取文本、译文、校对、任务与成本汇总、识别结论、经验总结、当前补丁和安装记录。游戏目录的备份、全局适配器与经验不在清理范围内。

清理不可撤销，失败或中断后可重新统计并继续。打开清理后的项目不会自动重建材料，已有译文和保留的补丁仍可使用。
