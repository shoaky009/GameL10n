# 数据目录与兼容

默认按 `%LOCALAPPDATA%\GameL10n` 的位置记录读取数据，也支持 `GAMEL10N_DATA`、旧变量 `AVG_TRANSLATOR_DATA` 和旧 `%LOCALAPPDATA%\AvgTranslator` 数据位置。命令行 `--data-directory` 优先。位置切换和迁移界面尚未接入。

现有 `games/index.json` v1 和 `games/<ID>/game.json` v2 可读取；列表使用摘要索引，只有索引不存在时根据 `game.json` 重建，不读取提取或模型会话。手工移走项目文件不会使索引记录自动消失，打开时报告缺失。

项目元数据的额外字段保留，不主动转换旧数据。已有 `settings.json`、翻译记忆、校对、原文快照、安装记录、适配会话、引擎经验和扩展目录原样保留；当前 Rust 入口尚未完整读取这些业务内容。受保护 API Key 的读取与旧译文指纹需要在相应模块接入时验证。

```text
<数据目录>/
  games/index.json                    兼容 v1 项目摘要
  games/<游戏ID>/
    game.json                         兼容 v2 项目元数据
    sources/<指纹>/                   当前原生脚本流程保存的原文快照
    extraction/native.json            Rust 原生解析流程的已提交结果、资源列表和哈希
    rust-task.json                    Rust 最近一次提取或构建任务结果
    patches/native-<唯一标识>/         经结构检查的补丁资源
```

新缓存不覆盖旧 `source.json`、提取目录、`task-state.json` 或译文数据。`extraction/native.json` 首次打开时加载，之后在内存复用；重新提取成功后原子替换。没有该文件时，按项目保存的原文指纹及适配器版本只读加载旧分资源提取缓存，保留原文、ID、顺序、说话人和保护标记，并核对清单及分片 SHA-256；损坏时报告错误，不触发重新解析。

内存缓存最多保留 4 个项目，并按约 128 MiB 的文本数据预算淘汰较早访问的项目。单个超过预算的当前项目仍可打开；切换后按需重新读取已提交文件，不重新提取游戏。普通配置与索引通过同目录临时文件写入后原子替换，不额外生成 `.bak`。

原始游戏目录作为输入，快照和补丁都写在项目域内。构建前检查快照哈希，回填时只应用明确提供的译文；未知 ID 由解析器拒绝。当前没有安装操作，不改写游戏文件。

完成的提取结果在重启后可读取，源快照可复用。提取或回填中断时不提交半成品，新任务仍可使用上一次成功结果。完整翻译请求恢复和智能适配会话续接尚未接入。

项目 ID 沿用规范化安装路径的 SHA-256 前 24 位；已有 ID 直接从索引保留。文件系统路径大小写、Unicode 大小写与旧序列化产生的缓存键不能随语言替换而改变。

只读诊断不取得写入锁，可检查正在由原程序使用的数据目录。首个修改操作复用 `.app.lock` 排除其他写入程序，并重新读取磁盘索引，避免把只读期间的旧列表覆盖回去；锁文件留在数据根目录。兼容读取不等于已经验证全部旧任务能继续执行。
