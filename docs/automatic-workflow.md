# 全自动汉化流程

每次打开识别对话框时，全自动流程默认关闭。在“识别游戏”中勾选“识别后自动试译验证、全量翻译并安装补丁”后，本次任务按项目流程配置执行。常规识别和强制智能识别都可以使用；修复和补全任务仍使用各自入口。

## 默认行为

1. 识别并提取文本，必要时继续智能适配。
2. 确定开场验证文本。优先使用运行检查中保存的唯一目标；否则启动原文游戏，执行已保存的场景操作，用 Windows OCR 匹配提取结果中的对白或旁白。
3. 翻译该文本，生成并安装试译补丁。
4. 启动游戏，执行场景操作，检查目标译文是否稳定出现在画面中，然后关闭本次启动的游戏及其子进程。
5. 检查通过后，全量翻译已提取文本，生成并安装全量补丁，结束任务。

流程不会把提取列表的第一项直接当作游戏第一句，也不依赖智能识别一定能推断开场顺序。默认操作为空；需要从菜单进入游戏时，先在“运行检查”保存按键、点击和等待操作。没有稳定文字、无法匹配或同一句对应多个文本 ID 时，任务进入“等待补充”，提示选择目标或调整场景，再重新开始。

自动定位会先恢复本程序已安装的补丁，以读取原文；恢复冲突会停止任务。已指定目标时跳过这一步。源语言按文本样本推测，可在定位步骤中指定；试译检查默认使用运行检查保存的目标语言。

## 调整流程

在“项目设置 → 编辑自动流程配置…”打开项目工作目录下的 `workflow.json`。首次打开或执行时创建默认配置，之后保留修改；每次启动流程重新读取，运行中的任务使用启动时的配置。

配置由入口 `entry` 和步骤数组 `steps` 组成。步骤成功后默认执行数组下一项；可用 `onSuccess`、`onFailure`、`onUnavailable` 指定另一项的 `id`。没有对应分支时，失败直接停止，信息不足则等待补充。下面是默认流程的简化配置，可直接使用：

```json
{
  "schemaVersion": 1,
  "entry": "recognize",
  "steps": [
    { "id": "recognize", "action": "recognize" },
    { "id": "locate", "action": "locateText", "onUnavailable": "input" },
    { "id": "trialTranslate", "action": "translate" },
    { "id": "trialBuild", "action": "buildPatch" },
    { "id": "trialInstall", "action": "installPatch" },
    { "id": "check", "action": "checkGame" },
    { "id": "translateAll", "action": "translate", "scope": "all" },
    { "id": "buildAll", "action": "buildPatch", "scope": "all" },
    { "id": "installAll", "action": "installPatch", "onSuccess": "done" },
    { "id": "input", "action": "waitForInput", "message": "请补充开场文本和场景操作后重新开始。" },
    { "id": "done", "action": "complete" }
  ]
}
```

| 动作 | 用途与可选字段 |
| --- | --- |
| `recognize` | 常规或强制智能识别，沿用启动时的选择；`instruction` 追加识别要求 |
| `locateText` | 确定验证目标；`unitId` 可直接指定文本 ID，`settings` 可指定原文 OCR 和场景操作 |
| `translate` | 翻译目标文本；`scope: "all"` 改为全量翻译 |
| `buildPatch` | 生成目标文本补丁；`scope: "all"` 改为全量补丁 |
| `installPatch` | 安装本次流程生成的最新补丁，沿用它的范围 |
| `checkGame` | 验证已安装的目标补丁并关闭进程；`settings` 可覆盖检查语言、区域和操作 |
| `waitForInput` | 结束当前任务并等待补充；`message` 为用户提示 |
| `complete` | 成功结束配置的流程 |

`settings` 与运行检查使用相同格式，例如：

```json
{
  "timeoutSeconds": 30,
  "language": "ja",
  "region": { "left": 0, "top": 60, "width": 100, "height": 40 },
  "steps": [
    { "action": "wait", "milliseconds": 1500 },
    { "action": "key", "key": "Enter" },
    { "action": "wait", "milliseconds": 2000 }
  ]
}
```

定位和译文检查可分别配置不同的语言或进入场景方式。只配置定位步骤时，后续检查复用其区域和操作，目标语言使用运行检查保存的语言。`unitId` 优先于保存的运行检查目标。已有提取结果的项目可把 `entry` 改为 `locate`，直接开始后续流程。

步骤 ID 必须唯一，分支须指向现有步骤。一次运行最多执行 64 个步骤，循环超过限制会停止。配置只编排上述领域动作，不执行任意脚本。即使改变分支，全量处理仍须有本次试译检查通过的结果；启动配置或目标译文变化后需重新检查，全量补丁还要求全部提取文本已有有效译文。

无界面入口同样复用配置：`gamel10n workflow <项目ID>`；`--intelligent` 强制智能识别，`--instruction` 补充识别要求。

## 失败、取消与检查边界

默认流程中，识别、翻译、构建、安装、启动、OCR 或进程关闭任一阶段失败，都停止后续操作，并在任务详情和日志中显示阶段及原因。游戏错误窗口会记录可读取的标题和正文。不会在报错后继续全量翻译或安装，也不会自动修复或反复重启游戏。

等待补充、取消和失败都会释放项目任务。重启应用后，未结束的流程显示中断阶段，不自动重放安装或启动操作。已保存的译文与补丁保留；重新启动从配置入口执行，并复用有效结果，不支持从任意节点自动恢复。失败不会自动回滚已安装的试译补丁，可使用“恢复原版”。

自动检查用 Windows Job Object 跟踪本次启动的进程树，关闭后才允许继续；取消、超时或检查组件退出时也会清理该进程树。用户原先启动的游戏不会被接管或关闭，须先退出。场景按键和点击需要游戏位于前台，失焦或目标被遮挡时停止。不同项目的运行检查共用桌面，同一时间只能执行一个。

OCR 通过表示目标译文在本次画面中稳定可读，可发现导致文字无法完整识别的缺字或截断；它无法证明所有字体、布局、分支及存档都正常，也不扩大已提取文本的覆盖范围。全量补丁安装后不再自动检查所有场景。运行条件见[游戏运行检查](desktop.md#游戏运行检查)。

自动启动游戏及补丁入口不属于 LLM 执行隔离。补丁可能包含生成的 EXE，运行它仍有宿主机风险；请使用可信模型和来源，详见[执行隔离的边界](adapters/execution-isolation.md)。
