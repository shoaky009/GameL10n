# 封包组件

> 完整产品的能力与协议参考；Rust 宿主的实际接入范围见[开发文档](../development.md)。

本文面向适配器开发者，说明内置封包组件的支持范围、输入输出和资源预算。组件使用发行包中固定版本的共享 Python 与 GalTransl 源码，不在分析期间安装模块或补下载内置工具。脚本的提取和回填由对应解析器负责。

| ID / 版本 | 支持范围 | 操作 |
|---|---|---|
| `archive.rpa3` / 2 | RPA/ARC 3.0，单分块，安全数据型 pickle 索引，流式读写 | inspect、extract、rebuild |
| `archive.xp3` / 1 | 标准 XP3 v1，已独立确认没有过滤器 | inspect、extract、rebuild |

RPA 不支持多分块和混淆；它只负责封包读写，编译脚本由 [RPYC2 固定流程](engines/renpy-rpyc.md)处理。XP3 不支持私有过滤器、加密、链式索引和 EXE 内嵌封包；标记为零不能证明没有过滤器，调用者必须提供 `filter: "none"`。组件成功只说明封包结构通过检查，不证明脚本覆盖、游戏补丁优先级或中文显示兼容。

## 输入、输出与校验

组件处理已暂存的真实封包，可按精确成员名或扩展名选择提取范围。所有成员均先检查路径冲突和越界，未选中的成员也不例外。

每次操作使用新的工作输出目录。完整成员名、长度与已读取内容的 SHA256 记录在 `manifest.json`；提取的文件放在 `files/`，调用结果只返回有界摘要。

RPA 的 `inspect` 只读取文件头与完整索引，`extract` 按选择读取脚本，图片和音频等未选中成员留在封包中。尚未读取的成员 `sha256` 为 `null`，不能将其当作已通过内容校验。`verifyContents: true` 会以有界缓冲区计算全部成员哈希；适配器完整验收使用此模式比较未修改成员。`inputBytes`、`selectedBytes`、`readBytes`、`allContentsVerified` 分别记录输入规模、选中成员规模、实际源文件读取字节数和是否已校验全部成员，供诊断分析使用。快速操作不计算整个输入封包哈希，`inputSha256` 为 `null`。

重建按精确成员名替换，未知成员报错；输出位于 `rebuilt/<原封包文件名>`。生成后重读封包，对比所有替换及未替换成员。没有实际修改时保留原封包字节；XP3 有修改时使用标准 v1 布局重建。

RPA 输入与输出封包、全部成员逻辑长度合计均限制为 2 GiB；按需提取的单成员和单个替换文件限制为 64 MiB，选中成员及替换内容分别合计不超过 256 MiB。未选中的媒体成员可超过 64 MiB，重建时流式保留并核对全部成员。XP3 仍限制输入封包 512 MiB、单成员 64 MiB、解码总量 256 MiB。两种组件均最多 10,000 个成员，成员名合计最多 2 MiB。

超限是当前组件预算限制；模块缺失或接口变化是共享工具版本问题，均不应解释为整个引擎不兼容。源码及解释器版本与哈希沿用现有共享依赖固定机制；后续发布的适配器不会自动换用新版本。

支持的封包与脚本组合可用 [组件组合模板](templates.md) 自动生成完整协议入口和发布依赖，省去逐次编写连接代码；仍须通过当前资源的完整适配器验收。
