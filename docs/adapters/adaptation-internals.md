# 智能适配的执行与恢复机制

本页面向流程维护与诊断。使用入口见[识别与智能适配](automatic-adaptation.md)，文件布局见[产物约定](artifacts.md)。

## 工具定义与请求开销

文件、历史、资源暂存、进展和反馈工具始终可用。其余定义通过 `load_tool_groups` 按需加载：`reuse`、`development`、`research`、`native`、`unity`、`siglus`，或 `all`。

`mode=add` 追加组，`mode=replace` 仅保留指定组，空数组只保留基础工具。宿主依据候选、已有实现和未完成调用预加载；压缩或恢复时结合近期最多四次助手响应重新选择，不回放全部历史定义。调用已注册但未展示的工具后会补入对应组，未知名称拒绝执行。

请求估算和日志使用实际发送的定义集合。维护提示时保持通用前缀稳定，引擎规则与完整指南按需读取。

## 已发布实现的复用

通过完整资源验收的新 Python 发布包可附带 `capability-profile.json`：绑定发布清单、资源识别条件、固定的宿主执行器及往返／中文复提／原资源完整性契约。文件不包含游戏资源、对话历史或来源游戏的验收通行证，也不改变适配器身份和版本。`inspect_adapter_source` 的索引会展示资料及可执行的验收配方；整包 `copy_adapter` 校验代码与固定依赖后，宿主可对当前已暂存资源连续执行该配方。旧包没有此资料，或资料的清单、契约、验收版本不匹配时，继续原有适配流程。源文件的选择性参考复制仍不自动验收或覆盖现有实现。

每次决策的 `capabilityGaps` 从现有宿主状态派生：缺少资源、可执行入口、验收参数、尚未通过的具体契约或待发布决定。该视图不另存一套事实。所有引擎共用状态与验收契约，引擎家族继续复用解析器、模板和字体组件，具体变体保留在已固定的 Python 实现、识别条件与参数中；不以引擎家族名称推断兼容。

`list_adapters` 和引擎经验中的发布版本提供 `inspect_adapter_source(id, version)` 入口。先分页列出清单文件，再通过 `path`、`query`、`offset` 和 `length` 读取所需源码片段；不会自动把完整实现加入上下文。文件索引每页最多 100 项，单个 UTF-8 文件最多 1 MiB，每次返回最多 16,384 个 UTF-16 字符。

`copy_adapter` 指定 `files` 时，仅将选定的发布文件复制到 `work/adapter-references/<id>/<version>/`。已有 `src` 不影响操作；每次最多 32 个文件、共 32 MiB，只核验所选文件的哈希，不覆盖不同内容，不修改当前适配器身份、依赖或发布清单。未指定 `files` 的整包复用仍要求空源码目录。

模型按容器、过滤器、脚本、编码、字体和加载规则分别判断适用性；某层不兼容时保留其他可用实现，参考文件接入 `src` 时须带齐导入、固定依赖和许可。复制与读取不授予兼容资格，也不作为实现或验收进展；正式产物仍经原有验收流程发布。

## 首次本地试用

已有适配器检查与常规识别共用发现流程。失败证据按资源、包、探测结果、固定依赖及验收版本核对，输入一致才复用；取消、扫描不完整和临时 I/O 故障不作为格式失败缓存。

首次新建适配在模型请求前试用裸脚本，优先有签名的格式：

| 项目 | 上限 |
| --- | --- |
| 格式与脚本 | 3 种格式，每种 2 个脚本 |
| 含伴随文件 | 每种 12 个文件，全部 64 MiB |
| 时间 | 总计 60 秒，每种 20 秒 |

样本暂存到 `resources/`，执行提取和原文字节回填，结果及有限预览写入会话。输入指纹一致可复用；已有实现、文本基线、修复或补全任务不重启试用。样本通过不授予发布资格。

## 首次自动组合

首次无补充要求、无已有实现的新建任务可自动使用[组合模板](templates.md)：裸 `.rpy`、`.ks`、RPYC2，以及 RPA3 中的 Ren’Py 源码、编译脚本或无冲突混合资源。禁用的模板和解析器不参与。

| 项目 | 上限 |
| --- | --- |
| 目录扫描 | 20,000 项 |
| 外层资源与封包 | 1,024 个资源、16 个封包 |
| 裸脚本／封包内脚本总量 | 256 MiB |
| RPA 输入／成员数 | 2 GiB／10,000 项 |
| 单个封包内源码／RPYC2 | 64 MiB／32 MiB（含槽解压总量） |
| 总时间 | 5 分钟 |

完整检查目录、索引、加载冲突和启动线索后，使用共用接口准备资源、验收和发布。通过后不调用模型；需要模型接手时才要求分析 API。未知结构、超限、不完整扫描或启动问题交给模型继续，已有实现和资源保留。

Ren’Py 路径条件见[混合资源](templates.md#renpy-混合资源)。XP3 由模型定向接入，须先独立确认无过滤器。发布前复核输入及完整目录事实；没有独立样本时覆盖为 `not-assessed`，实机状态保持未验证。

## 验收与结果复用

修复和补全任务将已有文本基线绑定到保存时的资源路径与哈希，读取对应的 `sources/` 制作输入；快照缺失时只接受哈希相同的原件。安装记录中其他被替换的文件取其原件，补丁新增文件及备份路径不作为制作输入。绑定保证与已有文本一致，不代表历史资源从未被外部修改。

文件工具的 `game` 视图、暂存、验收、发布及后续提取使用同一份输入。`installed` 视图及启动、文件定位诊断读取当前安装目录，供检查已安装补丁的问题。适配过程不要求恢复游戏或手动编辑会话记录来同步制作输入。

继续适配和验收前，主程序同步暂存副本与跟踪记录，更新与绑定输入不符的副本，移除不存在或已排除的文件，保留源码、发布清单和译文。`stage_resources` 默认追加或更新；`replace=true` 替换整个所选集合，同时移除未选副本并使资源验收缓存失效。暂存目录只保留已登记的资源，不保留中断复制留下的未登记副本。

`test_adapter` 对发布清单选中的 Python 源码执行语法、打包和资源验收。日志 `compileMs` 表示语法与准备阶段。

| 模式 | 参数 | 范围与资格 |
| --- | --- | --- |
| 仅探测 | `discoveryOnly=true` | 核对发现、元数据与受限片段，不授予发布资格 |
| 小范围试验 | `trialFiles` | 选择 1～12 个完整资源及依赖，独立缓存和构建，不授予发布资格 |
| 完整验收 | 省略以上参数 | 核对全部选中资源，可形成发布资格 |

`trialFiles` 与 `discoveryOnly` 不能同时使用。小范围试验保留正式资源规则，仅缩小输入；不能截断封包或省略必需依赖。

完整验收依次检查：

1. 制作输入与暂存资源发现一致。
2. 独立 `coverageSamples` 和修复基线的文本身份、位置、原文、上下文、说话人、类型及保护标记一致。
3. 原文逐字节往返。
4. 一至两条中文试写，复提并核对全部未改项。
5. 全量中文回填、复提、结构与路径检查。

任一阶段失败即停止。`pendingCoverage` 记录漏提文字，`runtimeChecks` 记录实机事项；省略参数保留原记录。存在待办时发布须指定 `finish.allowPartial=true` 并说明范围。

探测默认读取文件前 64 KiB；`probeReads` 可追加最多 4 轮、64 个片段，每片段 1 MiB，合计 8 MiB。仅探测只核对片段与元数据；完整验收对暂存、探测必需资源和转区配置做内容哈希，未选媒体不整包读取。

验收副本按内容哈希确认，操作结束及验收结束复核原始资源和副本。补丁复提读取声明的全部输出及伴随文件。输入变化、不可读或文件集合不完整时阻止通过；不以时间戳代替内容检查。

缓存指纹包括发布源码、依赖、清单、规则、发现依据、所选资源、独立样本、目标、修复基线及工具和验收版本。探测、试验和完整结果分别缓存；已完成的格式失败可复用，取消、超时和临时 I/O 错误不缓存。笔记和待办整理不触发重建。

完整验收的原文提取结果可经内存凭据交给 Core，核对项目原文快照与发布包后复用；重启或输入变化则正常提取。`validationContextVersion=1` 可复用当前校验已提取的源和产物，接口见[校验上下文](components.md#固定解析器与校验上下文)。

构建默认 `mode=replace`。`mode=overlay` 输出新增覆盖包，复提同时提供原资源与补丁，并传入 `buildMode:overlay`；适配器按已确认加载规则合并。仍核对全部文本、未改项及源和补丁哈希。

可选探测 `buildHints` 保存构建参数并由项目后续转发，例如固定覆盖卷路径。overlay 清单保存 `requiredSources` 哈希；安装先核对原文件或已记录备份，模式切换时恢复失效的旧输出，移除旧新增文件。恢复规则见[数据说明](../data-storage.md#保存与清理)。

## 固定工具依赖

分析和正式适配器使用共享 Python，固定解析组件使用 NativeAOT。源码参考、桥接模块和依赖哈希按发布清单保存，准备入口见[工具准备](../development.md#工具准备)。

VNTextPatch 原生依赖按内容哈希保留于 `extensions/engine-tools/native-vntextpatch`，跨项目共用。更新应用不替换适配器锁定版本；缺失或损坏时恢复原文件，或显式更新依赖并重新验收。

## 共享下载缓存

`extensions/downloads/` 按 URL 索引并校验内容哈希，跨项目复用。工作区使用独立副本，失败、取消或超限内容不登记缓存。

公共依赖即使与游戏中已安装的文件相同，也可随适配器发布；主程序通过内置组件或共享下载缓存中的来源凭据和文件哈希核实，不能仅凭模型填写的用途或工作区来源文件放行。

| 工具 | 行为 |
| --- | --- |
| `download_tool` | 优先使用 `src/tools/sources.json` 中哈希一致的项目依赖，其次共享缓存；单文件最多 256 MiB |
| `fetch_url` | 公开资料最多 8 MiB，缓存 7 天；过期刷新失败可返回 `stale=true` 的已校验副本 |
| `refresh=true` | 显式更新，失败时报错；工具依赖更新后重新验收 |

本地修改文件不自动覆盖。下载来源返回 `project`、`shared_cache` 或 `network`；成功日志显示文件和 URL。

### 公开资料与 GitHub 路径检索

`fetch_url` 默认 `mode=text`，`query` 为字面检索，`offset`／`length` 按 UTF-16 单元分页，默认 12,000、最多 24,000。HTML 解码后检索。

`mode=github_tree` 接受 GitHub `git/trees/{ref}` API，可用 `recursive=1`。按路径过滤后分页，默认 50、最多 100 条，返回 `nextOffset`、数量、`rawUrl` 和 `treeUrl`。`rawUrl` 固定 blob SHA，读取时直接取得原始内容。

`more` 表示本地余页；`upstreamTruncated=true` 表示上游目录不完整，此时须按子树继续，不能据空结果认定源码不存在。所有模式校验公开 HTTPS 主机、读取上限和缓存哈希。

## 引擎经验索引

自动注入最多 6 条相关短索引，适用条件最多 240 字符、摘要 200 字符。查询每页最多 12 条、6 KiB，按 `nextOffset` 继续。

详情按 ID 读取，来源数量默认单独显示；`inspect_engine_knowledge(id, sourceOffset=0)` 分页读取来源。保存或复用总结后按经验 ID 增量更新全局索引。

## 会话压缩与恢复

继续任务读取源码清单、暂存资源、验收结果、笔记和未完成步骤，跳过首次匹配。切换模型或协议保留这份进度快照。

恢复说明引用每次请求中的当前决策快照，不再复制一份完整状态或协议。检查点笔记保留记录轮次；笔记之后发生的实现变化单独标出，当前源码与最新宿主验收优先于历史模型判断。实验入口保留调用 ID、消息位置、脚本和报告哈希及输入版本，精确内容可定向回查。

每次模型请求由当前目标、约束、问题、假设、相关证据及最近最多四轮完整交互构成（超过四轮后按三轮步进滑动以保持请求前缀稳定），通常将交互控制在 64 KiB 内；最后一轮完整保留。发送前先选取交互，再生成工具预览，避免反复复制全部历史源码。问题改变时重新选择证据，目标或补充要求改变时清除旧问题和假设，已有源码与历史仍保留。旧版会话可从现有工具结果建立证据索引，无须重新调查。

工具结果首次发送后保持预览稳定，普通成功结果超过 8 KiB 时提供首尾与读取入口；重复结果引用已有内容。完整消息保存在[会话历史](../data-storage.md#提交与恢复)，通过 `read_tool_result` 或 `read_session_history` 查询，不重跑工具。

切换任务目标或更新补充要求时，宿主在下一次请求前保存阶段快照，避免修复任务持续重放最初开发阶段的全部工作历史；要求未变化的普通继续不触发此操作。当前目标内，资源发现、原文回填、局部试验或完整验收首次取得真实进展，且可见历史超过 64 KiB 或参与请求的原始历史超过 256 KiB 时，直接压缩历史，不额外要求模型生成总结。缓存验收和 `report_progress` 不触发阶段压缩，也不证明验收完成。

其他情况下，可见历史超过 192 KiB 或参与请求的原始历史超过 768 KiB 时提醒 `checkpoint`，未响应时宿主自动压缩。原始历史的阈值判定会扣除同一历史范围内由进程输出预览省略的内容，覆盖已移出当前决策窗口的交互；保留大段原始进程输出本身不要求额外生成摘要。阶段快照保留当前目标、最新用户要求、已有笔记、验证状态、源码和工作文件位置，以及最多八项失败工具的诊断摘录与原始证据位置；不会将单次工具失败推断为整条路线已被否定。各类压缩均保留最近最多四轮完整交互，通常控制在 64 KiB 内；最后一轮即使超出该上限也完整保留，避免丢失当前修改或拆散多工具结果。工具调用、结果和关联的 Responses 推理项成组保留，不局部改写推理。更早的精确消息、源码写入和失败输出仍可定向查回。

支持最多 6 项独立读取组成的批次，包含 `inspect_engine_reference`；参数必须已知，依赖前项结果的查询须另起批次。读取与进程运行不能混合。最多 8 项的顺序编辑批次中，前置项为 `write_file`／`replace_text`，最后可执行一次 `run_engine_python`／`run_tool`／`test_adapter`，末项计入上限。另可按 `stage_resources → compose_adapter_template → test_adapter` 连续执行，首末项可省略；每步参数必须已确定。拒绝信息列出收到的工具顺序，整个批次不执行。仍使用原有资源准备、模板和验收器，没有按模型说明推断出的自动发布。每项执行前后保存状态，前置失败或结果未确认时后续不执行；发布、checkpoint 和停止须单独调用。继续会话时，尚未开始的步骤可恢复，中断时正在执行及其依赖步骤须重新判断。

## 决策状态与实验报告

宿主在模板组合完成后自动使用其已确定参数验收；已有验收参数时，源码编辑完成后自动复验。仅探测或小范围试验通过会继续完整验收，发布仍需原有 `finish`。相同输入、实现和参数的自动验收不重复执行；失败或中断保留证据交给模型。修复任务没有新增工具证据、实现或方案变化时，不再次请求相同决策，保留任务供用户继续或补充线索；显式继续可重试一次。

`inspect_font_coverage` 是固定的字体实验：从工作区 UTF-8 译文 JSON（字符串数组或 ID 到字符串的对象）提取完整字符集合，一次检查至多四份 SFNT/TTC 字体的指定 face，支持非 BMP 字符。单文件至多 64 MiB、最多 100,000 个不同字符；返回有限缺字样例和内容哈希，完整结果保存到指定 `work/*.json`。格式无法解析或没有 Unicode cmap 时结果为未知；变体选择符等依赖字形序列的字符单列。检查不安装或转换字体，不修改译文，不授予运行验收资格。实际字体选择、Fallback、Atlas 和渲染继续由已有引擎组件及试译验证。

宿主验收的 `issues` 提供稳定失败类型、阶段、资源或文本 ID，以及有限的预期／实际差异；完整诊断与产物仍在原验收目录。会话 `repairs` 保存输入版本绑定的修复任务、尝试方案及实现版本，状态为 `OPEN → ANALYZING → PATCHED → VERIFYING → PASSED / FAILED`。相同失败保留任务 ID，不因重复验收生成新任务；输入变化后建立独立任务。小范围通过不能关闭完整验收失败，模型说明也不能将任务置为通过。`report_progress.repair` 可随实际操作记录方案，下一次决策包含旧尝试和是否新增验收证据。现有文本 ID、原文往返及发布资格判定不变。

文本字段不一致时，`fieldDifferences` 列出实际变化的字段名及有限的预期／实际值，普通诊断也标明字段名。检查范围沿用各阶段的身份契约；正文相同而 `speaker` 变化时，诊断显示说话者差异。顶层 `expected`／`actual` 对应首个变化字段，完整值仍以原始资源和验收产物为准。

会话的 `decision` 保存当前问题、模型假设与工具证据引用，不另存一套资源哈希、覆盖范围或验收结论。三层职责为：

| 层面 | 职责 |
| --- | --- |
| 所有引擎（`workflow`） | 问题状态、上下文构造、执行调度与统一验收 |
| 引擎家族（`engineFamily`） | 复用解析器、封包组件、组合模板及成批实验 |
| 具体配置（`engineVariant`） | 保存已确认布局、参数和字段规则，随现有适配器及固定依赖发布 |

`report_progress` 可在正常操作的同一次响应中附带 `problem`、`hypotheses` 与 `evidenceRefs`。问题 ID 保持稳定；改变 ID 会重选证据，并清除未再次提交的旧假设。假设状态 `open`／`supported`／`refuted` 均为模型判断，不授予兼容或发布资格。引用必须对应已经保存的工具结果，尚未执行的调用不能作为证据。

证据使用原始 `toolCallId` 和稳定的 `messageIndex` 定位，跨历史归档及重启仍可回查。引用附带当时已登记暂存资源哈希的摘要；摘要变化会在请求中标出，未知版本保留为未知。这只提示实验的输入范围，验收缓存的复用仍由既有指纹校验决定。原始消息、Responses 推理项和调用结果不因请求筛选而改写。

`run_engine_python` 可增加可选的 `questionId` 和 `reportFile`，一次执行遍历、筛选与比较，将完整报告保留在 `work/`：

```json
{
  "script": "work/check_candidates.py",
  "questionId": "archive-filter",
  "reportFile": "work/reports/filter-check.json"
}
```

脚本通过环境变量 `GAMEL10N_REPORT_FILE` 取得报告的绝对路径，不受 `workingDirectory` 影响；`GAMEL10N_QUESTION_ID` 提供问题 ID。报告须为至多 8 MiB 的 JSON 对象，含 `status=completed/partial/failed`；可选非负整数 `tested`／`matched`、字符串 `summary` 与字符串数组 `failures`，详细候选、字段和偏移可放在其他字段。

执行器向脚本注入 `write_report`，无需导入即可写入已声明的报告路径。例如：

```python
write_report(status='partial', tested=24, matched=2,
             summary='已确认两个候选，其余候选尚未完成检查',
             details=results)
```

`status` 必须由脚本按实际结论明确给出；执行器不会因退出码为零自动补写成功报告。手动写入 JSON 仍受同一契约检查。`executionSucceeded` 单独表示进程是否正常完成，报告缺失、未更新或无效时返回 `reportError`、目标路径及写入方式；已有进程输出和部分报告保留，修正报告问题前可直接回查。

工具回传状态、计数、有限摘要、最多四条代表性失败，以及脚本和报告哈希。完整报告用工作区文件工具读取，完整标准输出与错误输出经 `read_tool_result` 回查。报告缺失、未更新、格式无效或超限会明确报错；脚本失败时保留原进程诊断及可读的部分报告。自编报告属于实验观察，不能代替独立原文、中文回填和发布验收。

## 中断与停止判定

连续 24 轮无实现或验收进展时，在正常请求中提醒模型收敛；计数随会话保存，缓存重放和自报进度不刷新验收进展。提醒本身不终止任务或额外调用模型。

连续两轮只给总结而不执行工具时暂停。请求停止须说明尝试、证据和是否仍有可执行步骤；说明不足时要求继续，连续两次无工作则按未完成暂停。编码、字体或缺少现成解析器不单独构成无法适配的证据。所有继续操作受本次预算限制。

## 进展、结果与用户日志

`report_progress` 和明确的公开说明更新进展区，普通说明、模型突破及宿主验收分别标记。工具操作不清空已保存进展，切换项目按快照恢复，不额外请求模型汇报。

Token 旁的“第 X 轮”统计 API 请求，包含失败与重试，不包含工具执行；只能确认下限时显示“≥”。工具日志展示名称和主要对象，文件集合最多预览三项，不展示代码正文或命令参数。

任务异常、资源验收和支持范围分别记录。API 错误区分连接、超时、限流、鉴权、服务商故障、格式和拒绝；下载错误独立处理。界面显示失败原因和恢复方式，预算、取消和等待信息各有对应状态。

## 进程、调度与日志

工具以当前用户权限运行，宿主限制路径、时间和输出，取消时终止进程；这些限制不构成操作系统沙箱。

每个游戏同时一个任务，智能适配并发为一个游戏，与其他游戏的常规识别和翻译独立调度。API 名额按请求占用，本地工具执行期间释放。

`logs/adaptation-yyyyMMdd.jsonl` 按天记录，以 `runId` 区分开始或继续：

| 数据 | 含义 |
| --- | --- |
| 构建、模型、预算、思考等级 | 本次执行配置 |
| API 耗时与排队时间 | 网络和服务端处理、宿主等待分别统计 |
| 输入、输出与 `cachedTokens` | 服务商用量，缓存属于输入，缺失与零值区分 |
| `cacheHitRate`、`missingCacheUsage` | 有缓存计数请求的缓存／输入总量，以及计数缺失请求数 |
| 上下文与工具定义大小 | 实际请求、保留历史和裁剪规模 |
| `contextComponents`、`toolDefinitionFingerprint` | 决策快照、旧证据、补入协议、近期交互及回读预览大小，工具定义集合是否改变 |
| `verificationConfigured` | 本次请求前是否已有可自动复用的验收参数 |
| `decisionHistoryStart`、`decisionEvidenceCount`、`problemId` | 当前请求选取的历史起点、证据数量与问题 |
| 调用 ID、参数指纹、路径、范围与诊断 | 定位工具执行和重复工作 |
| `resultFingerprint`、脚本与报告哈希 | 区分同参不同结果、相同输出及实验代码变化 |
| 进程退出码、报告错误与报告计数 | 区分脚本运行失败、报告契约失败和部分样本不匹配 |
| `verification-phase`、`fingerprintStats` | 验收阶段、修改条数、哈希与探测的读取规模 |
| `automatic-template` | 模板阶段、输入／脚本／实际读取量及脚本和媒体包数量 |

成功请求正文和源码写入内容不复制到诊断日志，API 异常写入 `api-*.json`。日志 URL 移除凭据和查询参数。缓存命中只记本次耗时，不累计历史耗时。

`contextComponents` 记录可见内容的 UTF-8 大小，沿用上下文预算的计量方式，不是供应商 Token 分项。`decisionMessageBytes` 与 `recentHistoryBytes` 组成可见历史；快照、证据及补入协议是决策消息的组成部分，回读大小则是近期交互的子集，不能重复相加。回读同时记录保留原文与实际发送预览的大小；旧日志缺失这些字段时保持未知。

`scripts/analyze-adaptation-log.ps1 -ProjectDirectory <项目目录>` 输出 Token、耗时、大输出及验收摘要；`-RunId`、`-Since`、`-Until`、`-FromTurn`、`-ToTurn` 限定范围，`-Detail` 展开请求分项、相同输出、拒绝的批次及上下文压缩前后对比。工具总数和耗时包含已结束的宿主自动步骤，`modelToolCalls` 与 `hostSteps` 分别计数，验收记录以 `caller` 标明来源。重复参数或相同输出只表示候选重复工作，仍须结合输入变化与用途判断；缺少结束记录不能仅由日志反推任务状态。
