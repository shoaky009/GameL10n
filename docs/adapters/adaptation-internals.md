# 智能适配的执行与恢复机制

面向维护智能适配流程、排查耗时与恢复问题的开发者。界面行为和使用限制见[识别与智能适配](automatic-adaptation.md)，文件用途见[产物与目录约定](artifacts.md)。

## 工具定义与请求开销

工具定义按需提供。文件、历史、资源暂存、进展、摘要和阻碍反馈始终可用；请求附带简短能力目录，模型通过 `load_tool_groups` 追加 `reuse`、`development`、`research`、`native`、`unity` 或 `siglus`，不确定时可用 `all` 补齐全部工具。已有引擎候选或经验会预加载复用组，现有源码、协议或修复任务会预加载开发组，已固定的共享工具库会预加载研究组，Siglus 候选会预加载专用检查。程序在每轮请求前检查这些线索，因此复制模板后可直接进入开发与验证。加载只修改本地会话，不下载或运行工具；加载后的组在本次会话持续保留，摘要、重启和切换模型均不会收回。

恢复旧会话时，程序也从完整历史和待执行调用补齐工具组。模型直接调用已注册但未展示定义的工具时仍可执行，后续请求自动提供对应组；未知工具名仍拒绝。连续只返回总结时，首次提醒继续操作前会补齐全部定义，仍受原有轮数和 Token 预算限制。Token 预算估算和耗时日志使用本轮实际提供的定义集合。

## 首次本地试用

开始新建适配时，已有适配器检查与常规识别共用 `AdapterDiscoveryService`。常规识别由 Core 准备原文快照，候选通过后才提交项目的识别结果。其外置适配器失败证据可交给随后发起的智能适配：仍重新探测，并核对资源内容、包内容、探测结果、固定共享依赖、工具链版本和宿主验收版本；输入相同才跳过已完成的失败验收。扫描不完整、取消或临时读写错误不复用，输入变化重新检查。证据保存到适配会话，模型直接取得失败阶段与相关源码位置。

新建适配在首次模型请求前自动试用少量裸脚本：优先带脚本签名的候选，最多 3 种格式，每种最多 2 个脚本，加上必需伴随文件后每种最多 12 个文件，所有样本合计不超过 64 MiB。原始资源只读，样本暂存到 `resources/`；宿主直接执行提取与原文逐字节回填，将数量、最多两个简短文本预览及具体错误交给模型，不需要模型先调用目录、暂存和试提取工具。自动试用总预算 60 秒，每种格式最多 20 秒；超时、工具缺失及资源变化均作为未完成证据，不判定引擎不受支持，也不触发额外下载。

自动结果保存在原有会话中，指纹包含所选文件路径与内容、解析器及启动文件内容和试用规则版本。首次分析被中断后继续时，相同输入复用已完成结果；变化后重新试用，取消和临时故障不缓存为格式失败。进入模型分析或已有源码后，继续任务沿用保存的证据，不自动重启起步试验；修复、覆盖扩展、已禁用的格式和已有文本基线也不会触发自动试用。少量样本通过本身不会授予发布资格。

## 首次自动组合

首次新建适配在模型请求前还会尝试明确受支持的组合：纯裸 `.rpy`、纯裸 `.ks`，或 RPA3 封包中的 Ren’Py `.rpy` 源码。宿主检查完整目录、封包版本与全部成员，暂存全部规则匹配资源后，调用 `AdapterDevelopmentWorkflow` 的组合、验收和发布方法；模型工具也调用同一组强类型方法。通过后发布并启用当前版本，本次不发出模型请求、不消耗分析 Token。模型通过工厂延迟创建，未配置分析 API 不影响本地组合；需要模型接手时才报告配置问题并保存进度。

此路径只处理无补充要求、无已有实现的新建 Develop 任务；修复、覆盖扩展、已有文本基线、恢复中的会话及复用失败后的继续开发仍交给原有模型流程。模板 family 或底层解析器 family 被禁用时不自动组合。已有源码不会被模板覆盖。

自动组合最多检查 20,000 个目录项，选择 1～1,024 个资源、最多 16 个封包，输入合计不超过 256 MiB；封包成员合计最多 10,000 项、解码后不超过 256 MiB，并保留组件自身的单文件及安全限制。总时间预算为 5 分钟。扫描不完整、超限、封包与裸脚本混用、已识别的其他脚本格式、编译脚本或嵌套封包都会交回模型，不能忽略它们后只发布少量样本。存在启动配置、启动脚本、已知错误日志或不完整启动检查时，也先交给模型解释这些证据。XP3 目前不进入自动组合，因为没有独立的无过滤器证据；零标记、签名或可解包均不构成该证据。

发布前复查判断模板适用范围所依赖的完整目录事实，目录文件集合变化或检查不完整时取消自动发布资格。原始资源及副本哈希、源码、依赖、资源发现、独立原文样本、原字节往返、完整及部分中文回填仍使用正常验收规则。没有独立样本时文字覆盖仍为 `not-assessed`，不会把适配器自身提取的文字转作独立证据；自动发布只确认模板选中的源脚本范围，不宣称整款游戏文字已全部覆盖。游戏启动、字体、中文显示和排版始终标为未实机验证。

自动组合的阶段、具体失败和封包清单路径保存在现有 `session.json`，源码、全部已暂存资源及清单保留在工作区。无法完成时，首个模型请求直接获得这些记录，沿用已生成实现处理缺口；恢复会话不重新启动自动新建流程。未通过完整验收不会自动发布，也不会因超时或工具资产缺失将格式判为不支持。

## 验收与结果复用

继续完善已有适配器时，使用独立定位的原文样本核对提取结果。`checkpoint` 和 `test_adapter` 接受 `coverageSamples`（资源路径、字段定位、原文），程序逐项检查，可发现读写双方共同使用错误字段偏移的问题。修复任务已有提取记录时，程序直接核对原有文本的 ID、位置、原文、上下文、说话人、类型和保护标记，防止修复让译文或校对记录失效；智能体通过 `inspect_existing_text` 按需分页查看字段，全量记录留在本地。

`pendingCoverage` 保存已确认的漏提文字；`runtimeChecks` 单独保存需要进入游戏验证的启动或显示事项，不作为文字覆盖缺口。省略参数不会清除记录，压缩对话和重启后仍保留。修复任务可以披露其他范围的已知遗漏后完成，无需自动扩展到所有文字类别。记录有数量与长度限制，不另建数据库或逐条文件。

有已知待办时，发布必须明确选择部分支持（`finish.allowPartial=true`）并说明原因，结果仍显示未覆盖项。独立样本核对、资源往返和游戏实际显示是不同的验证范围；有限样本不能证明全游戏文字已完整提取。只有样本或源码等验证输入变化才需重新验证，单纯整理待办不会触发重新编译。

`test_adapter` 先比较真实游戏与暂存样本的探测结果，报告缺少或多出的必需文件及启动入口差异，再执行完整验收。`discoveryOnly=true` 可提前检查探测逻辑，但不会授予发布资格。探测从每个文件前 64KB 开始；需要包尾、索引或 PE 资源时，适配器通过 `probeReads` 请求有限片段，由宿主在本地提供后再次调用探测。最多追加 4 轮、64 个片段，每片段不超过 1MiB，总量不超过 8MiB。索引读取不需要复制完整媒体封包，也不调用模型。

相同验收输入复用最近一次已完成的结果，保存在现有 `session.json`，主动摘要和重启后仍有效。指纹包含正式源码与依赖的内容、发布清单、资源规则与识别声明、真实游戏及暂存目录中相关资源的文件集合与内容、独立原文样本、任务目标、修复基线、工具链版本和宿主验收版本。命中时仍检查输入哈希、编译产物与固定共享依赖的完整性；探测或回填检查结果返回 `reused=true`，编译失败则沿用原错误，省去重复编译和资源往返。资源已变化却未重新暂存时仍报错；文件集合不完整时不缓存。

完整验收、仅探测和失败结果分别处理。已完成的编译或结构失败可复用原诊断，修改相关输入后重新执行；取消、超时和临时文件读写失败不缓存。仅探测通过或失败结果均不会授予发布资格。调查笔记、已知遗漏说明和运行验证待办不改变资源验收输入，返回结果仍显示最新待办；游戏内运行效果始终另行验证。

## 共享下载缓存

额外工具和在线资料共用 `<数据目录>/extensions/downloads/` 中按 URL 索引、内容哈希校验的持久缓存，跨项目和重启复用。同一 URL 的并发请求合并准备，取消、失败和超限下载不登记为可用缓存。`download_tool` 默认复用缓存；当前项目 `src/tools/sources.json` 已登记且文件哈希一致时优先保留该依赖，不随其他项目刷新而变更。本地文件有修改时拒绝覆盖；需要从上游更新时显式传 `refresh=true`，并重新验收适配器。目标路径和发布登记规则不变，工具单文件仍限制 256 MiB；工作区文件是独立副本，编辑不会改变共享缓存。

其他在线资料通过 `fetch_url` 按需读取，每份上限 8 MiB；超限明确报错，不将截断结果当成完整目录。共享缓存有效期为 7 天，`refresh=true` 可立即请求当前内容；返回原始获取时间、内容哈希、`reused`、`stale` 及后续阅读位置。过期资料更新遇到网络失败时可返回哈希校验通过的旧副本，并以 `stale=true` 标明；显式刷新失败和用户取消仍报错。单次适配在内存中最多缓存 4 份、合计 12M 字符。GitHub 仓库元数据搜索也复用共享资料缓存，支持显式刷新。在线 `main` 资料可能更新，与已固定共享版本不同；开发应优先读取实际调用版本的本地指南和源码。访问失败不代表格式不支持。

## 会话压缩与恢复

继续时跳过初次适配器匹配，向模型提供现有源码清单、已准备的资源、最近验证结果和已有调查笔记，直接处理未完成步骤。切换模型后也会提供这份进度快照。长会话先提示智能体调用 `checkpoint` 保存已确认结论、排除的方案和下一步；若下一轮仍未执行，程序自动缩短请求历史。快照、摘要和原始消息仍保存在同一份会话文件中。

压缩阈值按可见内容计算，不把 JSON 转义开销或 Responses 的加密推理内容当作待总结文本。后续调用需要的原始推理数据仍随当前会话保留。摘要记录结论和证据文件位置，详细源码和分析输出留在已有文件中。

宿主支持独立的只读查询批次，以及最多 8 项的顺序写入／运行批次。后者的前置项为 `write_file` 或 `replace_text`，最后一项还可为一次 `run_csharp`、`run_engine_python` 或 `run_tool`。每项结果单独持久化；前置操作失败或中断且结果未确认时，后续步骤标记为未执行。已成功提交的写入可从下一步继续。暂存、依赖复制、验收、发布和 `checkpoint` 不参与这些批次。

请求保持最新一轮工具结果完整，其他成功结果按 64KiB 预算从近到远保留；不再只因经过三轮就缩短结果。超过预算或重复的大结果发送索引和短预览，重复结果注明仍可见的相同副本；失败信息保持完整。原始结果仍在 `session.json` 中，可通过 `read_tool_result` 按范围或关键词读回，不需要重新执行工具，也不另建结果文件。

发送的可见历史超过 192KiB，或当前参与请求的原始历史超过 768KiB 时，请求模型调用 `checkpoint`；不因小消息数量单独触发。模型摘要优先控制在 3000 字内，保留当前实现需要的字段顺序、数组步长、接口约定和覆盖遗漏。主动摘要保留最近最多四轮完整工具交互；忽略提醒时，程序保留 64KiB 内的近期完整交互，并补入当前目标、已存结论、验证状态、资源与源码位置及近期证据索引。工具调用与结果成组保留，Provider 原始响应不作局部修改。已经读取的适配器协议也会随压缩和恢复快照提供。

程序自动整理的快照不替代模型的逆向结论。压缩、主动 `checkpoint` 和切换模型只改变参与请求的历史起点，旧消息完整留在 `session.json`，重启后仍可查回。`read_tool_result` 按工具调用 ID 分页读取原始结果；`read_session_history` 按消息位置或关键词读取旧分析与完整工具参数，不重跑实验，也不额外请求摘要模型。旧版本会话已经删除的历史无法恢复。

常驻提示集中于通用协议、实现目标及验证要求，引擎和组件的详细规则按需读取。连续 24 轮没有观察到源码写入、组件复用或完整验收通过时，在下一次正常请求中提醒模型核对现有成果，优先完成可验证的实现步骤。计数保存在现有会话中，压缩或继续不会重置；相同内容的源码写入不会重置计数。这只是收敛提醒，不判定研究无效、不自动终止任务，也不额外调用模型；外部工具直接修改源码时可能仍会出现提醒。恢复较长的旧会话时也会先核对一次。资源验证与实际游戏运行验证始终分开，不能为节省 Token 降低回填验收要求。

耗时日志区分发送的可见历史大小、保留历史大小和被缩短的工具结果数量，Token 用量仍采用 API 返回值，便于比较实际输入开销。

## 中断与停止判定

编码、字体或回填验证失败不会授予发布资格。模型只返回阶段总结时，程序会要求它继续执行工具；连续两轮只给总结则停止，保留进度并提示继续或更换分析 API。所有继续操作仍受本次 Token 和轮数预算限制。

模型报告无法适配时，还须说明是否存在本地可执行的后续工作，并提供具体尝试、结果及证据位置。存在后续步骤或说明缺失时，程序要求继续执行；连续两次只请求停止、没有开展其他工作时，按“适配未完成”暂停并保存下一步，避免无限重复。此判定约束模型提交的停止说明，不代表程序能独立证明某引擎不可支持。编码限制、未完成的字体分析、缺少现成解析器或搜索无结果本身不足以作出无法适配的结论。

## 进程、调度与日志

工具以当前用户权限运行普通本地进程，不使用 AppContainer。宿主对路径、执行时间和输出进行检查，取消时终止进程；这些检查不构成操作系统级隔离。原游戏通过内置读取操作调查，开发工具使用选择的资源副本。

同一游戏同时执行一个任务。智能适配同时运行一个游戏，与其他游戏的常规识别和翻译分别调度；同一 API 按单次模型请求排队，本地编译期间释放 API 名额。

项目的 `logs/adaptation-yyyyMMdd.jsonl` 记录每轮 API 和工具耗时、分析思考等级、上下文大小、Token 用量及执行状态。API 耗时包含网络与服务端处理，另记本地 API 队列等待时间，不能将其直接视为模型思考时间。每天追加到同一个文件，不复制成功请求、响应或工具正文；工具失败时记录简短诊断，详细 API 异常沿用 `api-*.json` 日志。

日志按 `runId` 区分每次开始或继续，记录程序构建标识、实际模型名称、预算以及常驻提示和工具定义的字节数。工具条目包含调用 ID、参数指纹、文件路径／读取范围等定位字段和精简结果；不保存源码写入内容、查询正文、命令行或标准输入。公开资料 URL 去掉凭据、查询参数和片段。验证失败保留具体原因，验证耗时分为编译、识别和回填验收，避免后续会话压缩后失去诊断。

开发者可运行 `scripts/analyze-adaptation-log.ps1 -ProjectDirectory <项目目录>`，只读输出 Token、耗时、最近六轮及关键失败的紧凑摘要。`-RunId`、`-Since`、`-Until` 限定调查范围，`-Detail` 展开逐请求统计、重复参数及 checkpoint 前后对比。截断请求的用量与后续恢复事件关联计入一次；未知用量明确保留为缺失。没有结束记录不代表任务仍在执行。参数重复须结合输入和源码是否改变及上次结果判断，源码修改统计包含 `write_file` 和 `replace_text`，外部工具修改不一定被计入。旧日志缺少的信息不会反推或伪造。
