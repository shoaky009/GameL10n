# 引擎分析产物与目录约定

引擎分析涉及五类文件：正式适配器、汉化运行文件、可续接的开发资料、单次执行临时文件，以及日志和全局经验。文件扩展名不能决定其用途；例如 Python 脚本既可能是分析探针，也可能是正式适配器依赖。

以下路径以应用的数据目录为起点。默认位置为 `%LOCALAPPDATA%\AvgTranslator`，可在“程序设置”更改。目录按需创建，不要求每个项目都具备所有文件。

## 可续接的开发资料

每个项目的当前开发目录是 `games/<项目 ID>/adaptation/current/`。

| 相对当前开发目录的位置 | 用途 | 发布时的处理 | 保留方式 |
| --- | --- | --- | --- |
| `src/**/*.cs`，排除 `src/tools/` | 候选适配器的解析、提取、回填及验证代码 | 参与编译，并保留源码副本 | 继续适配时原地修改 |
| `src/tools/**` | 适配器运行所需的脚本、DLL、EXE、配置、数据和许可声明 | 整个目录复制到正式包的 `tools/` | 与源码一同保留 |
| `work/**` | 临时分析入口、探针、解包结果、报告和笔记 | 不打包 | 保留供继续调查和总结使用 |
| `work/status.md` | 调查状态与结论笔记，可选 | 不打包 | 恢复会话时会读取其中的有限内容 |
| `resources/**` | 从游戏选择并复制的资源、主程序、字体及转区配置等验证输入 | 不打包 | 保留，原文件哈希记录在会话中 |
| `build/**` | 最近一次编译的程序、源码副本和工具依赖 | 验收通过后从这里发布 | 下次编译时替换 |
| `session.json` | 会话消息、工具结果、已确认结论、Token、覆盖范围、待办、验证状态及下一步 | 不打包 | 原子更新，供暂停、重启及继续适配恢复 |

源码位于 `src/` 不代表已发布或已验收。`build/` 也只是开发中的构建结果；会话可能引用其中已验证的包，发布前删除会影响继续发布。

文件放置遵循以下约定：

- 临时 C# 测试入口、Python 调查脚本和 PowerShell 分析脚本放在 `work/`，复用已有 `src/` 解析代码，不把测试入口混入适配器编译。
- 只有适配器正常识别、提取、回填或验证需要的依赖才放入 `src/tools/`。需要随包携带的非 C# 配置、数据和许可文件也放在这里；`src/` 其他位置的非 C# 文件不会自动打包。
- 正式依赖通过包内路径定位，例如 `AppContext.BaseDirectory/tools`，不应依赖开发时的 `work/`、`resources/` 或绝对项目路径。
- 分析笔记与工具结论优先复用已有文件，不为每次检查另建目录、备份或完整源码副本。

任务完成、失败或暂停后，`current/` 都会保留。过程资料不属于玩家的汉化运行文件，但仍可能用于继续修复、扩展覆盖或生成全局经验，不能将整个目录视为单次执行后即删除的临时目录。

## 正式适配器

通过完整 `test_adapter` 后，`finish` 再次核对源码、依赖和资源与验收输入一致，才发布并激活版本。Manifest v2 的正式包位于：

```text
extensions/packages/<引擎或模板 ID>/<版本>/
  adapter.dll                  编译后的适配器程序
  adapter.runtimeconfig.json   固定 .NET 运行时要求
  src/                         适配器 C# 源码
  tools/                       随包依赖，按需存在
  package.json                 身份、版本、资源规则、协议版本和文件哈希
  verification.json            宿主验收时间与诊断，运行验证单独标记
```

C# 源码由宿主编译为 `adapter.dll`，通过应用附带的 .NET 工具链执行，不解释执行源码。版本根据包内容等输入生成，已发布版本固定；失败的开发任务不会替换现有激活版本。旧 Manifest v1 包可能在包根目录保留 `Program.cs`，不具备相同的多文件目录结构。

目前打包按路径选择文件，包清单没有逐文件的“分析脚本／运行依赖”等角色声明。`src/tools/` 中误放的临时文件也会进入包；正式包文件清单和哈希校验不能代替对依赖用途的检查。

原文往返、中文回填与重新提取、部分试译保留原文等属于资源验收。`verification.json` 在发布时记录 `runtimeTested=false`，不证明游戏启动、字体、换行、分支和存档可用。完整验收规则见[智能适配](automatic-adaptation.md#验证与产物)。验收样本、详细调查依据和部分待办仍主要保存在项目会话及工作资料中，正式包不包含完整调查档案。

以下全局文件与正式包相关，但用途不同：

| 位置 | 用途 |
| --- | --- |
| `extensions/catalog/` | 按引擎或模板保存游戏版本、资源指纹与兼容记录 |
| `extensions/games/` | 保存项目当前激活版本及上一版本的引用 |
| `extensions/library-index.json` | 引擎库展示摘要，可重建，不替代运行校验 |
| `extensions/engine-tools/` | 共享引擎源码库、便携 Python 与固定版本记录 |

使用共享 Python 引擎库的适配器，会在包内保存固定依赖记录和调用桥，实际工具位于 `extensions/engine-tools/`。这类正式适配器并非仅复制自己的包目录就能独立执行；共享工具也不能一概视为临时下载文件。完整依赖准备方式见[智能适配](automatic-adaptation.md)。

## 汉化运行文件与补丁记录

汉化补丁位于 `games/<项目 ID>/patches/<构建标识>/`，由适配器使用原文快照和译文生成。

| 内容 | 用途 | 是否安装到游戏目录 |
| --- | --- | --- |
| 汉化资源、必要的 EXE／启动器、字体和运行依赖 | 游戏实际运行需要的文件 | 按补丁清单安装 |
| `patch-manifest.json` | 安装文件路径及哈希 | 不安装 |
| `translation-report.json` | 本次生成结果、限制和验证说明 | 不安装 |
| `translation-snapshot.json` | 本次补丁使用的译文快照 | 不安装 |

安装后的游戏只需要补丁声明的运行文件，不依赖制作工具、适配器、分析脚本或模型服务。补丁清单和报告留在项目中；安装记录保存在项目的 `installation.json`。替换游戏原文件前仍按安装规则保留 `.bak`，见[安装与恢复](../usage.md#安装与恢复)。

`resources/` 中的分析样本与项目 `sources/` 中用于翻译及补丁重建的原文快照用途不同，目前可能同时保留副本。正式包发布后，项目中的 `src/`、`build/` 与全局包也可能同时存在；发布不会自动归档或删除这些开发资料。

## 单次执行临时文件

下表中的项目内路径相对 `games/<项目 ID>/`；正式包的发布暂存目录位于全局扩展目录。

| 位置 | 内容 | 正常结束时的处理 |
| --- | --- | --- |
| `adaptation/current/work/.run-csharp-*` | 一次 C# 探针的临时程序集与引用副本 | 删除临时编译目录，保留脚本源码 |
| `adaptation/current/verification/` | 原文往返、中文修改和部分文本补丁等验收输出 | 验收退出时删除，诊断写回会话 |
| `adaptation/reuse-*`、`adaptation/reuse-check/` | 复用适配器时的资源验收工作目录 | 验收退出时删除 |
| `adaptation/run-*` | 一次适配器调用的文件头、响应、译文输入及临时输出 | 调用退出时删除，正式构建文件复制到补丁目录 |
| `adaptation/current/build.compile-*`、正式包旁的 `.pending-*` | 编译或发布尚未提交的目录 | 成功时移动为目标目录，正常失败时移除 |

临时 C# 脚本通过 `run_csharp` 显式选择源码编译运行。Python 脚本通过 `run_engine_python` 使用共享解释器运行；PowerShell 或工作区工具可通过 `run_tool` 执行。脚本自行写入 `work/` 的报告和解包文件属于开发资料，不会因本次执行结束而一并删除。

临时目录删除是尽力执行。进程被强制结束、目录不可写或文件被占用时可能残留，不能保证每次都清除；程序没有后台扫描清理历史开发目录的功能。

## 日志与全局经验

| 位置 | 用途 | 保留方式 |
| --- | --- | --- |
| 项目 `logs/adaptation-日期.jsonl` | API／工具耗时、Token、调用定位、精简结果与状态 | 按天追加，不保存成功 API 请求响应正文 |
| 项目 `logs/` 中的异常诊断 | API 异常、适配失败原因等 | 保留用于排查 |
| 项目 `engine-review.json` | 最近一次总结的结论、证据指纹、消耗和全局条目引用 | 总结时更新 |
| `extensions/engine-knowledge/*.json` | 同引擎适用条件、指引和可复用辅助源码 | 全局保留，按条件供智能识别选用 |

全局经验由“总结”功能产生，可以没有新增条目。它不是已验证适配器；其中的辅助源码复用到其他游戏前，仍需核对适用条件并通过该游戏的验收。

## 删除与重新开始

需要完全重新分析时，先停止任务，再手动删除对应项目的 `adaptation/current/`。这会丢失其中的会话、源码、样本和调查资料，但不会删除译文缓存、已发布适配器或已生成的补丁。只删除个别工作文件可能使恢复笔记或已保存验证引用失效。

正式适配器版本通过“全局引擎库”管理，仅允许删除未被项目引用的外置版本。删除整个项目数据目录会同时影响译文、原文快照、补丁与安装恢复记录，范围大于重新分析，见[使用、备份与续译](../usage.md)。
