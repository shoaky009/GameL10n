# 组件组合模板

> 完整产品的能力与协议参考；Rust 宿主的实际接入范围见[开发文档](../development.md)。

组合模板为适配器开发者提供固定的协议入口、资源发现、共享解析器连接和发布依赖。适用范围内的封包与脚本组合可以复用同一实现，特殊格式和运行条件仍需单独适配。

| 模板 ID | 封包组件 | 脚本解析器 | 默认资源规则 |
|---|---|---|---|
| `loose-renpy` | 无 | Renpy / `.rpy` | `**/*.rpy` |
| `loose-kirikiri-ks` | 无 | KirikiriKs / `.ks` | `**/*.ks` |
| `rpa3-renpy` | `archive.rpa3` / 2 | Renpy / `.rpy` | `**/*.rpa` |
| `loose-renpy-rpyc` | 无 | RPYC2 惰性 AST / `.rpyc` | `**/*.rpyc` |
| `rpa3-renpy-rpyc` | `archive.rpa3` / 2 | RPYC2 惰性 AST / `.rpyc` | `**/*.rpa` |
| `renpy-mixed` | `archive.rpa3` / 2（有封包时） | Renpy 源码 + RPYC2 惰性 AST | `**/*.rpy`、`**/*.rpyc`、`**/*.rpa` |
| `xp3-kirikiri-ks` | `archive.xp3` / 1 | KirikiriKs / `.ks` | `**/*.xp3` |

封包支持范围和预算见 [引擎组件](engine-components.md)，编译脚本范围见 [Ren’Py RPYC2](engines/renpy-rpyc.md)。`renpy-mixed` 按资源类型连接现有解析器，接受路径无冲突的源码、编译脚本和封包组合。XP3 必须先独立确认未使用过滤器，配置才可声明 `filter: "none"`；生成模板并不证明某个游戏属于这个范围。

模板先检查所有目标文件。有任何不同内容或目录冲突时，保留已有修改且不写入模板文件；相同文件直接复用。依赖及入口写入 `src/`，配置为 `src/tools/adapter-template.json`。模板通过共享 Python 入口连接固定组件，使用发行包已有的工具，不复制 DLL、解释器或整套库到项目，也不安装第三方模块。

模板接入后仍需使用规则匹配的真实资源，完成独立原文样本核对、提取、原字节回填、少量中文试写及全量中文回填验收；单独生成模板不会验证、发布或启用适配器。首次新建适配的宿主自动流程可以对符合条件的前六种组合完成资源准备、完整验收和发布，适用条件及预算见[执行与恢复机制](adaptation-internals.md#首次自动组合)。XP3 仍需独立确认过滤器后定向处理。发布后的操作按固定协议运行，不需要调用模型。已发布版本继续使用固定哈希的组件依赖。

## Ren’Py 混合资源

`renpy-mixed` 先读取全部封包索引，在统一的资源路径中检查加载冲突，再提取脚本。封包必须位于同一目录，以该目录作为加载根；松散脚本也须位于此根内。例如 `game/story.rpa` 的 `chapters/start.rpyc` 与 `game/intro.rpy` 可以组合，而与 `game/chapters/start.rpy` 会因同名脚本冲突而停止。检查忽略路径大小写，将 `.rpy` 与 `.rpyc` 视为同一脚本名，也拒绝不同封包中的重复脚本。

不同章节可以分别采用源码或编译格式，也可以分布在松散文件和封包中。纯媒体封包仅查索引，构建时复制原字节，最终验收仍核对其全部成员。加载根不明确、模块或同名覆盖关系需要继续分析，模板不会自行推断覆盖优先级。没有封包的源码／编译脚本组合也可使用此模板。

## 连接行为

封包及 RPYC2 探测只检查提供的头部，完整解析留在提取、构建和验证阶段，避免将 64 KiB 探测样本当作损坏的完整资源。只将选定扩展名的脚本解包到临时目录；其他成员留在原封包中。

单元的 `resourcePath` 指向外层封包，`locator` 包含内层脚本与解析器位置；ID 由外层路径和稳定的解析器 ID 构成。不同封包里同名脚本不会相互覆盖，译文长度改变不会改变身份。构建时按封包路由译文，未知 ID 会报错；未修改的封包直接复制原字节，有修改的封包重打包后比较全部成员。验证同时重读脚本结构，检查未选择的成员没有改变。

RPYC2 部分使用共享库的惰性解析器；纯 RPYC2 模板不连接 VNTextPatch 或 C# 组件宿主，混合模板仅将 `.rpy` 交给现有源码解析器。ID 与位置取自文件、节点身份、行号、文本角色和选项位置，不包含随译文增长变化的 Pickle 字节偏移。多个封包提供同一 RPYC 路径时不自动选择优先级。

编码沿用现有解析器：Ren’Py 保留 UTF-8/BOM 策略，Kirikiri KS 使用现有的读取和 UTF-16 写回规则。编码可写不代表游戏运行时接受该编码。字体、转区、私有过滤器和特定引擎版本的运行补丁仍须根据当前游戏证据补充；可继续复用现有编码/字体组件，不能自动套用其他引擎的策略。运行状态始终保持 `not-tested`，直到另有实机验证。
