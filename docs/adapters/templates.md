# 组件组合模板

组合模板为适配器开发者提供固定的协议入口、资源发现、共享解析器连接和发布依赖。适用范围内的封包与脚本组合可以复用同一实现，特殊格式和运行条件仍需单独适配。

| 模板 ID | 封包组件 | 脚本解析器 | 默认资源规则 |
|---|---|---|---|
| `loose-renpy` | 无 | Renpy / `.rpy` | `**/*.rpy` |
| `loose-kirikiri-ks` | 无 | KirikiriKs / `.ks` | `**/*.ks` |
| `rpa3-renpy` | `archive.rpa3` / 2 | Renpy / `.rpy` | `**/*.rpa` |
| `xp3-kirikiri-ks` | `archive.xp3` / 1 | KirikiriKs / `.ks` | `**/*.xp3` |

封包支持范围和预算见 [引擎组件](engine-components.md)。Ren’Py 编译脚本 RPYC 不在本模板范围内。XP3 必须先独立确认未使用过滤器，配置才可声明 `filter: "none"`；生成模板并不证明某个游戏属于这个范围。

模板先检查所有目标文件。有任何不同内容或目录冲突时，保留已有修改且不写入模板文件；相同文件直接复用。依赖及入口写入 `src/`，配置为 `src/tools/adapter-template.json`。模板通过共享 Python 入口连接固定组件，使用发行包已有的工具，不复制 DLL、解释器或整套库到项目，也不安装第三方模块。

模板接入后仍需使用规则匹配的真实资源，完成独立原文样本核对、提取、原字节回填、完整中文与部分中文回填验收；单独生成模板不会验证、发布或启用适配器。首次新建适配的宿主自动流程可以对符合条件的前三种组合完成资源准备、完整验收和发布，适用条件及预算见[执行与恢复机制](adaptation-internals.md#首次自动组合)。XP3 仍需独立确认过滤器后定向处理。发布后的操作按固定协议运行，不需要调用模型。已发布版本继续使用固定哈希的组件依赖。

## 连接行为

封包探测只检查提供的头部，完整解析留在提取、构建和验证阶段，避免将 64 KiB 探测样本当作损坏的完整封包。只将选定扩展名的源脚本解包到临时目录；其他成员留在原封包中。

单元的 `resourcePath` 指向外层封包，`locator` 包含内层脚本与解析器位置；ID 由外层路径和稳定的解析器 ID 构成。不同封包里同名脚本不会相互覆盖，译文长度改变不会改变身份。构建时按封包路由译文，未知 ID 会报错；未修改的封包直接复制原字节，有修改的封包重打包后比较全部成员。验证同时重读脚本结构，检查未选择的成员没有改变。

编码沿用现有解析器：Ren’Py 保留 UTF-8/BOM 策略，Kirikiri KS 使用现有的读取和 UTF-16 写回规则。编码可写不代表游戏运行时接受该编码。字体、转区、私有过滤器和特定引擎版本的运行补丁仍须根据当前游戏证据补充；可继续复用现有编码/字体组件，不能自动套用其他引擎的策略。运行状态始终保持 `not-tested`，直到另有实机验证。
