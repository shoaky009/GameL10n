# Ren’Py RPYC2 编译脚本

智能适配可以直接组合松散 `.rpyc` 或 `.rpa` 封包中的 RPYC2 脚本，接受 RPA-3.0 / ARC-3.0 签名，无需先反编译为 `.rpy`，也不需要模型编写解析和回填代码。满足自动组合条件且完整验收通过时，可不调用分析模型完成适配器发布。正文翻译仍按项目选择的翻译服务执行。

## 支持范围

- 脚本头为 `RENPY RPC2`，包含源码 AST 槽 1，以及可选的转换后 AST 槽 2；两槽的文本身份与内容必须一致。
- 提取 `Say` / `TranslateSay` 的对白与旁白、`Menu` 的选项、`TranslateString.new` 的显示文字。静态角色名作为只读上下文；不翻译角色声明、查找键 `old`、Python 或 screen 代码中的字符串。
- 共享库解释 Pickle 协议 2–5 的支持子集，将类名、构造操作、memo 别名和循环保留为数据，不导入 Ren’Py、不实例化游戏对象、不执行游戏代码。
- 回填同时修改对应槽，保留控制符、变量插值、节点身份、跳转、条件、Python、未知非文本字段和末尾的 16 字节源码 MD5。此摘要描述原始源码，不按译文重新计算。

RPYC2 槽表及源码摘要的含义可参阅 [Ren’Py 的脚本加载实现](https://github.com/renpy/renpy/blob/master/renpy/script.py)。解析器接受的具体对象结构由固定版本共享库决定，不将文件头匹配视为完整兼容。

## 自动处理与限制

自动组合先扫描完整文件列表；RPA 只读取完整索引来选择源码或编译脚本流程，媒体不解包。源码与编译脚本混用、封包与松散脚本混用、`_ren.py` / `.rpym` / `.rpymc` 模块、不同封包提供同一路径脚本时，保留诊断交由后续分析确认加载顺序。引擎附带脚本与游戏脚本尚未自动区分；这种混合安装目录也可能需要定向选择资源。

单个 RPYC2 文件及所有槽解压数据合计不超过 32 MiB，选中脚本合计不超过 256 MiB。自动流程最多 1,024 个外层资源、16 个封包；封包成员、输入及输出预算沿用 [RPA 组件](../engine-components.md)。旧版 RPYC、加扰文件、未知额外槽、异常对象结构或两槽不一致均明确失败，不绕过检查。

验收先检查原文逐字节往返，再试写一至两条中文，核对全部未修改文本，通过后才执行全量中文回填。最终验证从原始对象图重建允许的文本修改，并与补丁字节比较；封包中的未修改媒体也必须保持一致。仅局部通过不会发布。

适配器使用发行包中固定哈希的 Python 与共享库，不安装 pip 包或在分析中下载反编译器。打包与组合阶段会检查 RPYC2 模块是否存在；旧工具库缺少模块时提示恢复完整发行包，不在当前分析中自动升级，也不将其归因于引擎不兼容。

资源验收不能确认游戏实际加载效果；中文字体、排版、启动及当前游戏独立文字覆盖仍需另行验证。`verification-phase` 记录验收阶段、耗时及修改条数，`automatic-template` 记录所选模板、失败阶段、输入与选中脚本规模及索引实际读取量。
