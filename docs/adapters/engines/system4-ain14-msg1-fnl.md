# AliceSoft System4 AIN 与 FNL

## AIN 对话

首次识别发现 AI2 封装的 `.ain` 后，会解压核对 `VERS`、`CODE` 和 `MSG1` 布局。消息表有明确边界、全部槽位可按同一种已支持编码读取时，宿主可组合 `system4-ain-msg1` 模板。模板按消息槽位提取和变长回填，保留原始槽位顺序及其余资源字节。

组件支持 `CODE` 后紧接 `FUNC`、`MSG1` 后紧接 `MAIN` 的布局，按完整消息表检验 CP932 和 GBK。编码有多个候选或均无法解码时，结构试验仍可供分析复用。CP932 资源中的不可编码译文需要当前游戏支持的编码或字形映射。小样回读通过后，已选脚本进入完整资源验收，独立界面文字、`STR0`、EX 字段及运行显示继续核对。

可通过 `try_builtin_adapter` 使用 `system4-ain` 试验完整样本，也可复制该组件接入已核对的显示路径。现有项目扩展覆盖时沿用原有消息槽位与文本 ID 的对应关系。

## FNL 补字

内置 `system4-fnl-glyph` 组件提供 Windows GDI 宋体单色位图生成，供适配器按原 FNL 字形尺寸补字。调用方式见[字体组件接口](../components.md#字体与启动器)。

组件接收字符、宽高与参考位图，检查字体替换和非空字形；不负责 AIN 消息提取、FNL 文件读写、码位分配或 EXE 修补。这些步骤须由当前适配器确认，并保留原字形和文本身份。

FNL 文件布局、字符容量和运行时码位支持须分别验收。实际显示与排版通过游戏内试译确认。
