# KiriKiri SMIL / SmileCrypt / PSB SCN

内置标识为 `engine.kirikiri-smil-smile`。适用于 `File/smil` 索引和当前已确认 SmileCrypt 参数配置的独立 XP3，不按游戏名称识别，也不将 SMIL 标签当作过滤器证据。探测解析名称映射并验证两个实际成员的解密校验与脚本结构，其他过滤器配置继续交给已有候选及智能适配。

## 文本与身份

支持 PSB v2/v3 SCN 的正文、显示姓名、选项和场景标题，KS 的直接正文，以及 TJS 源码中 `caption`、`hint`、`title` 的静态字符串。SCN 按原树路径标识字段；资源路径、原始成员别名及字段定位共同构成文本身份，不因校验值或译文长度改变而重建 ID。

可读文件名通过 SMIL 映射恢复，原始别名保留用于回填。原生 ASCII 大小写规则与工具生成的 Unicode 大小写别名分别匹配，不能先统一转换整个成员名称。保护用启动条目和真实启动脚本可能恢复为同名，二者不合并。编译 TJS 按二进制识别并保留，不将常量池中的资源标识或逻辑字符串当作玩家文字。

没有剧情结构的 PSB 资源不作为剧情提取。遇到未确认的 SCN 控制符或派生数据，保留对应原文字段并报告范围，其余独立字段仍可提取和回填。其他动态界面、宏属性、字符串表、编译 TJS 显示消费者及图片视频内文字尚未全面覆盖。

## 回填与验证

未修改构建保持原字节。修改构建使用同路径替换封包，保留前缀、受支持的保护声明、原始别名、时间字段和未修改成员压缩数据；同步更新成员及 SMIL 映射中的校验标识。未知索引字段、保护声明布局或模糊映射会拒绝，不猜测丢弃。

SCN 复用固定 PSB/SCN 读写器，修改消息时更新已确认的可见长度和朗读、搜索数据。只修改实际受影响的记录；保留未确认字段的原值。源码脚本在原编码不能表示中文时改用带 BOM 的 UTF-16LE。

资源验收分别检查原文逐字节回填、中文修改、部分翻译后的重新提取，以及全部未修改文本与身份。验收上下文可复用已经提取的原文和输出文本，不为校验再次全量解析。资源验收不能证明字体、排版、签名检查和原游戏启动；这些仍需使用原有启动环境做游戏内验证。
