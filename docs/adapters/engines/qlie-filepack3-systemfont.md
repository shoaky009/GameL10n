# QLIE 封包适配、字体与启动组件

## 封包脚本模板

两个模板支持 ImoScripter（`FormatType=1`、`ReturnCode=[n]`）及早期 `Library/Avg`（`library/avg/setting.txt` 含 `DefaultFormat=Multi`、`scenario/*.s` 行式剧情脚本）两种已确认脚本配置，按同一启动目录下 `GameData` 的封包版本选择索引、密钥和回包实现。

- `qlie-pack3-imos` 适用于 `FilePackVer3.0` 与 `HashVer1.3` / `HashVer1.4`（含 256 桶文件名哈希、桶位置、序号核验及 `PACKKEY` 链式签名校验）。模板用 EXE 的 `IconKeyImage` 和 `DLL/key.fkey` 读取每卷的内部密钥，按原字节保留匹配的 EXE 和转区配置。ImoScripter CP932 脚本同样保护 `[rb,正文,注音]` 标签（含 `[pc,...]` 内嵌注音）、忽略索引赋值辅助脚本并保留 `【甲】【乙】` 连写人名的原身份分隔；`Library/Avg` 方言保留 `【原身份＠译名】` 与 `[f,N]` 等非换行控制标签，并同步替换系统脚本中的 `\fn2` 字体名及默认配置字体。
- `qlie-pack31-imos` 适用于 `FilePackVer3.1`、`HashVer1.4`（含 `PACKHASH` 头部、256 桶文件名哈希/桶位置/序号核验与 `PACKKEY` 链式签名校验）和首项内置密钥布局。按成员识别脚本编码，UTF-16 保留字节序和 BOM，CP932 脚本可使用下述字形映射。`[rb,正文,注音]` 作为完整标签保护。

模板核对各卷的脚本配置，从索引中选出脚本和配置所需的卷。按原封包及成员路径区分同名脚本，提取对白、人名、选项及已识别的显示字段。回包保留成员顺序及查找表，验收会回读改写成员并校验其他成员的原字节。卷的覆盖顺序、系统文本、中文显示及排版需单独确认。

生成试译或正式补丁时，若不同卷内的同路径脚本解包后逐字节相同，所选字段的译文也会写入副本中的对应位置。各卷保留独立的文本 ID。副本已有不同译文时，可以分别选中并写入各自的译文。同路径脚本内容有差异时按卷单独处理。

自动组合 3.1 时，目录外的同名副本需要与安装卷大小和 SHA-256 一致。根目录的卸载器封包需要有卸载程序引用，且索引中的资源限于位图、图标和文本。其余封包需要确认加载和文字覆盖范围。遇到未知或混合的 FilePack 版本时，诊断会记录各卷版本和索引阶段，供后续确认读写布局。[智能适配流程](../automatic-adaptation.md)

## 系统字体布局

3.0 模板检查外置 `GameData/System/config.txt` 和卷内唯一的 `system/font/fontdata.dat`。支持 0 到 7 号单层字体布局，使用 MS Gothic 或 MS Mincho 的 `system`、`system_fix` 字体，可按 `fontdata.dat` 规则保留封包内已存在的 `.of` 位图外字槽（如第 6 号 `外字` 或第 5 号 `外字登録`，并兼容字体列表中的 `<名称>.of` 引用）。若卷内存在 `script/config/default.txt` 的默认字体或系统脚本中的 `\fn2` 字体设置，补丁会同步更新。其他布局仍可使用严格 CP932 的提取和回填。

3.1 模板按根目录中成对出现的游戏 EXE 和同名 `.exe.le.config` 确定日语转区入口。双层布局使用卷内 `system/font/fontdata.txt`，0 号槽包含 `system`、`system_ext`，其余七个槽继承 `base`。

对于已验证的 IMOSURUME 2.2.0.0 运行时，启动脚本会调用合并 `Avg/ImoScripter_FontList.txt` 与 `Avg/Setting.txt` 的字体初始化例程。此布局的私用码位可能显示为引擎图标。含译文的 CP932 剧本改用带 BOM 的 UTF-16LE，直接写入中文，已有 Unicode 剧本保留字节序。对白使用 Windows 微软雅黑（Microsoft YaHei），普通启动和恢复默认字体都会在各槽继承前设置该字体，保留字号、样式及玩家的外置配置。试译与全量翻译使用相同规则，通过 LE 启动原 EXE。适配验收回读实际剧本编码、译文及启动字体选择。Unicode 脚本的识别可参考 [VNTextPatch 的 QLIE 读取器](../../../third_party/VNTextPatch/Scripts/QlieScript.cs)。

对于已有剧本替换表、对白替换指令（含 `ImoScripter_Custom.s` 回显阶段替换或 `ImoScripter_Format.s` `Imo_FormatModeMulti` 入口统一替换）和第 6 号外字槽的 ImoScripter 布局，模板使用游戏自带的 OF 位图字体。CP932 无法表示的 BMP 字符使用剧本标签，替换表在显示时切换到位图槽并恢复原字体。补丁将中文字形写入字库的空闲位置，保留原有图标，可沿用原游戏的启动方式。支持带 64 像素方格的索引色字形页。补字以 Windows 宋体为底稿，适度加粗细笔画，减少缩到对白字号时的断笔。验收从封包回读标签、替换规则和字形像素。存档标题需要单独确认替换入口。

封包读取器和文字显示能力分别匹配。接入其他 FilePack 版本时，先确认索引、密钥和回包能往返，再按实际脚本编码、字体槽和显示指令选择已有方案。其余已支持的系统字体布局按逐文件编码处理。需要使用私用字形时，模板更新外置配置与卷内字体表，使用配套启动器加载字体。

使用配套启动器的布局遇到 CP932 无法往返的译文时，模板跳过脚本及字体配置中已用的双字节码位，给新增字符分配字形，生成对应的 Noto SC 衍生字体和启动配置。补丁保留字形映射和 OFL 许可。再次提取时按原封包、成员和字段回读译文，沿用既有文本 ID。

启动器随使用私用字形的补丁交付。原版资源上的译文都能按脚本原编码往返时，可以沿用游戏原有的启动方式。对于从玩家配置恢复基础字体、再将它复制到对白槽的 ImoScripter 初始化脚本，模板会在复制前选择补丁字体。已识别的明朝体和哥特体分别使用对应的衬线和无衬线字体，其他名称使用该布局的默认字体。验收从回包后的初始化脚本读取各分支选用的字体。

匹配的游戏可在首轮模型请求前完成原文逐字节验收、少量中文试写和全量中文回填验收。生成 Noto SC 衍生字体时，宿主从固定上游获取字体和许可，校验 SHA-256 后存入共享下载缓存。首次缺缓存时需要联网。此类补丁随附生成的字体及许可。系统文本、实际游戏显示及排版仍需确认。[智能适配流程](../automatic-adaptation.md) · [字体来源和哈希](../../../third_party/qlie-fonts/sources.json)

部分和全量试译都会用宿主内置的 QLIE 读取器（支持 ImoScripter 与 `Library/Avg` 方言）核对改写的字段。对非模板自定义适配器，若原封包使用宿主尚未登记的尾表版本（但成员索引与脚本可读），独立显示回读器仍会继续核对译文字段、字体选择及位图/SFNT 字形，并在验收诊断中标明文件名查找表未由宿主独立核验；若原封包使用已登记尾表，回包产物仍须通过完整尾表核验。脚本使用 CP932 私用码位承载中文时，宿主会沿卷内字体表、外置配置、默认配置、脚本 `\fn2` 指令和配套启动器核对游戏选择的字体，并检查替代码位与目标汉字在字体中指向同一字形。对于未登记脚本方言却包含私用字形或启动资源的补丁，宿主回读会明确拒绝而非跳过核验。已有 FilePack 适配器首次复用时会补做本地验收，同一适配器、资源内容和验收版本可复用通过结果。

## 字体组件接口

`qlie-sfnt-font` 提供其他已确认单字体布局所需的独立字体试验。模板使用按需准备的字体素材和 `qlie-japanese-font-launcher`。单独检查素材时可用 `inspect_adapter_component` 查询 `qlie-systemfont-assets` 的固定下载地址及哈希，使用 `download_tool` 下载到 `work/`。

用 `component("qlie_font", request, input=..., output=..., family=..., map=...)` 生成配套 SFNT 字体。配置名使用字体 `name` 表 ID 4 的完整 Regular 名称，保留原有外字槽并附字体许可。[组件接口](../components.md#接入与版本管理)

复制 `qlie-sfnt-font` 后，运行组件说明中的 `probeCall`，传入一个解包的 CP932 脚本、候选 SFNT 字体和已确认可用的码位。小样会试写简体字、复读译文并生成配套字体。正式适配仍需验收整包回填和游戏显示。

## 启动组件接入与构建

通过补丁的 `QlieLauncher.exe` 启动。它读取 `qlie-l10n/launch.xml` 并为当前游戏加载配套字体。配置路径相对启动器，`face` 须和字体内部名称一致。需要转区时使用玩家安装的 Locale Emulator，并保留原 EXE 和对应转区配置。

用 `scripts/build_qlie_launcher.py` 构建 Windows x64 Rust 启动器，输出至 `target/runtime/adapter-components`。启动自检后需在原游戏中确认字体选择与显示。[启动器源码](../../../tools/GameL10n.QlieLauncher) · [工具准备](../../development.md#工具准备)
