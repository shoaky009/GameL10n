# 识别与智能适配

“识别游戏”先尝试复用已有适配器或本地模板，需要调查未知格式时才调用分析模型。添加或打开项目后，由你主动开始识别。

## 选择适配目标

| 入口 | 适用情况 |
| --- | --- |
| 识别游戏 | 首次提取，或在文本删除后恢复识别。已有项目优先尝试该游戏通过资源验收的版本。 |
| 强制智能识别 | 跳过常规匹配，把已有实现和资源交给分析模型调查。 |
| 修复现有问题 | 处理乱码、字体、启动或回填故障，同时验证已有文本和译文的兼容性。 |
| 补全遗漏文字 | 扩展提取范围，复用仍匹配的译文。 |

在补充要求里写明问题位置、原文、报错或启动方式。少量提取结果可能显示“覆盖待确认”，程序会继续查找主要文本资源。确属小体量的游戏也需确认覆盖。[识别声明与诊断](recognition.md)

提取范围是已识别的玩家可见文本，例如对白、选项、菜单和说明。图片、视频及尚未识别的文本来源需要另行处理。翻译完成数以提取结果为准。

## 总结经验

“总结经验”在后台读取当前项目的适配记录。总结期间可以翻译、校对或生成补丁。项目任务区同时显示运行中的任务。展开各自的详情可查看进度和用量，点击“停止总结”或“暂停翻译”可单独停止对应任务。

同一项目一次可运行一项总结。重新识别、修改适配器或清理总结正在读取的适配资料与日志时，需要先结束总结。

## 进度与继续

智能适配使用支持函数工具调用的分析 API。Token 预算不足时保存工作，点击继续可使用新的本次预算。切换模型或协议后，已保存的源码与调查进度仍可使用。[模型接口配置](../model-providers.md#智能适配预算)

工具调用或资源验收失败后，宿主将具体原因交给分析模型，继续在本次 Token 预算内处理。模型确认需要用户提供资料或操作时，可以暂停并说明下一步。已有具体尝试和结果表明本地无法继续时，模型可以报告无法适配。

点击“继续适配”会沿用已保存的失败详情、源码和小样。仅记录退出码的旧失败会在再次验收时刷新错误详情。

首次调用模型前，宿主用已有资源清单挑选少量封包，按需读取脚本和伴随文件。EAGLS SCPACK、Artemis PFS v8、BGI、KIF、YPF 482 和 NEKOPACK4A 的小样可检查提取、原文往返及译文回读。CatSystem2 加密 KIF 需要可由同目录 EXE 和成员签名交叉验证的命名密钥。YSTB 试验需要同目录的 `ysc.ybn`。格式、编码或依赖不符时，后续调查可复用已通过的小样结果。[封包组件](templates.md#封包组件) · [EAGLS 脚本](engines/eagls-scpack.md) · [Artemis PFS](engines/artemis-pfs.md) · [NekoSDK](engines/nekosdk.md)

NekoSDK 或 QLIE 封包小样通过后，宿主可在请求模型前组装适配器，验收提取、整卷原文回填和译文回读。QLIE 3.1 小样需要通过改写成员的回包和回读。索引、关键配置、小样封包及所用组件和参考库一致时，可复用已通过的小样。已有符合样本的中文回填配方时优先复用。需要处理译文编码、补充文字覆盖或确认游戏显示时，分析模型可以沿用已有实现和验收结果。[NekoSDK 适用范围](engines/nekosdk.md) · [QLIE 适用范围](engines/qlie-filepack3-systemfont.md#封包脚本模板)

适配可检索公开资料、下载依赖并向分析服务发送必要的资源片段与工具结果。工作区保留会话、源码和报告，供修复或总结使用。[适配产物](artifacts.md) · [执行隔离](execution-isolation.md)

## 验证与产物

资源验收检查提取、原文逐字节回填、部分及完整翻译的复提和文本身份。小样通过可作为调查依据，发布需要完整验收。部分支持的结果会列出适用范围和已知遗漏。

Artemis PFS v8 替换式适配器的部分试译如果发现说话人身份变化，宿主会尝试用同一组试译输入复测相关 AST 成员。小样重现原差异时直接返回该错误，修正后再做完整验收。

进度会区分当前资源回填通过、主文本覆盖待确认和已登记的文字遗漏。提取量偏小、缺少独立原文样本且有暂存资源未纳入验收范围时，宿主等分析模型重新确认范围后再做完整验收。

资源验收通过后，先对容易找到的对白或界面做试译，再进游戏检查画面、分支和存档。运行结果单独记录。[桌面操作](../desktop.md) · [全自动汉化流程](../automatic-workflow.md)

## 版本反馈与修复

新版本通过资源验收后可供当前项目使用。在“补丁与验证”记录“效果正常”后，其他项目才可自动复用。一个游戏的失败反馈会排除该游戏对该版本的自动匹配。

待游戏内确认的适配器可在智能适配中提供源码和验收配方。已有封包小样通过解析和原字节往返时，会优先提示同一模板的已验证实现。复用时按当前启动范围选择脚本文件，并对当前游戏重新做完整资源验收。

“有问题，继续修复”会记录问题并打开修复配置。新版通过当前补丁的运行确认后，程序可清理较早的适配器版本，并保留其他项目使用的版本。已有译文与补丁仍可使用。[引擎库管理](README.md#引擎库管理)

## 诊断

在任务详情和项目日志查看当前阶段、失败原因与验收结果。本地准备日志记录识别证据和自动试用或模板筛选的跳过原因。工具操作记录带简短的目标和参数，读取范围可用来区分分段读取和重复读取。开发者可从源码目录汇总适配日志。

```powershell
./scripts/analyze-adaptation-log.ps1 -ProjectDirectory 'D:\GameL10n Data\games\项目ID'
```

用 `-RunId` 限定单次运行，`-Detail` 查看逐轮用量、工具、小样和复验步骤。服务商是否命中缓存以返回的用量为准。核对任务状态后再判断缺少结束记录的步骤。[日志汇总脚本](../../scripts/analyze-adaptation-log.ps1) · [会话编排](../../crates/engines/src/adaptation_flow.rs) · [验收实现](../../crates/engines/src/adaptation_verification.rs)
