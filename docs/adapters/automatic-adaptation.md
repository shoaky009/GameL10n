# 识别与智能适配

常规识别复用已有适配器；智能适配调用分析模型，调查资源并开发提取和回填能力。

## 选择适配目标

| 入口 | 行为 |
| --- | --- |
| 识别游戏 | 先常规匹配并提取；无可用适配器或不足 1,000 条文本时继续智能检查 |
| 强制智能识别 | 跳过常规匹配和本地自动完成，复用资料交给模型检查 |
| 修复现有问题 | 处理编码、字体、启动或回填问题，保留已有文本身份和译文匹配 |
| 补全遗漏文字 | 扩展覆盖后重新提取，复用仍兼容的译文 |

补充要求可写明界面位置、遗漏原文、启动方式和报错。少量文本只是检查线索，小体量游戏无需达到固定条数。转入智能检查时保留已提取结果，缺少 API 或检查失败也不删除已有数据。

候选适配器在探测后以 `errorKind: "incompatible"` 明确报告资源格式或过滤器不支持时，记录失败原因并继续检查其他候选；全部不兼容时进入智能适配。未分类失败、工具缺失、执行故障及原资源被修改等错误会停止任务，不能把所有提取异常都归为格式不兼容。

已有项目优先使用其当前适配器；固定了其他适配器的项目不会自动切换到新增的 SMIL 配置，修复时须验证已有文本身份。尚未固定适配器的 XP3 项目会先进行有界的 KiriKiri SMIL 配置探测，确认映射、过滤器校验及脚本样本后才选择资源；其他变体继续原有候选流程。

智能适配中断、失败或预算用尽后，再次识别直接恢复未完成的会话与原目标，跳过常规匹配。已完成适配的项目再次识别仍从常规匹配开始。

适配范围包括剧情、菜单、界面、物品、装备、技能、教程和提示中的玩家可见文字。图片与视频内文字、内部标识、资源路径和程序逻辑不在提取范围。翻译完成数仅针对已提取文本。

## 模型与预算

分析 API 须支持函数工具调用。预算、轮数和项目覆盖规则见[模型接口配置](../model-providers.md#按用途选择)；达到上限保存进度，继续时使用新的本次预算。

首次适配会先试用已有解析器，并尝试明确支持的[组合模板](templates.md)。本地完整验收通过即可发布，无需分析 API；其余情况将资源、源码及失败证据交给模型。修复、补全和已有会话直接沿用保存的工作。适用条件与预算见[执行机制](adaptation-internals.md#首次自动组合)。

## 本地工具、联网与下载

发行包提供 Python、固定解析工具和共享引擎库，缺失时需恢复完整工具版本。模型可检索公开资料并下载额外依赖；日志显示文件、来源 URL 和缓存来源，共享缓存跨项目复用。

进入模型上下文的是必要资源片段、文本和工具结果，不默认上传完整游戏。分析工具以当前用户权限运行，受路径、时间和输出限制，但没有操作系统级沙箱。开发与验收使用副本，安装补丁是独立操作。

## 验证与产物

发布前检查提取、原文逐字节回填、完整和部分中文回填、复提、文本身份及输出路径。源码、依赖或资源变化后须重新验收。修复任务还对照原有提取基线，保留译文和校对匹配。

| 结果 | 含义 |
| --- | --- |
| 少量样本通过 | 当前解析器可能适用，仍需完整验收 |
| 资源验收通过 | 受支持范围满足提取和回填检查 |
| 部分支持 | 已验证范围可用，并列出已知遗漏 |
| 游戏运行记录 | 用户已检查该补丁的实际表现 |

资源验收后，选择能在游戏中找到的少量文本试译，确认启动、中文、换行、分支和存档。需要转区时沿用原环境；生成独立启动器时使用补丁指定入口。

正式适配器保存于全局扩展目录，项目固定其版本。玩家运行已安装补丁只需游戏运行文件。已有证据明确覆盖加载规则且有可复用构建能力时，优先输出只含修改成员与必要伴随资源的新增补丁；其余情况使用替换补丁。不为补丁体积增加模型研究、下载、加载器开发或验收阶段。协议见[验收机制](adaptation-internals.md#验收与结果复用)，引擎示例见[Artemis PFS](engines/artemis-pfs.md)。

## 版本反馈与修复

新发布版本标为“待游戏验证”，当前项目可用；在“补丁与验证”记录“效果正常”后，其他项目才可自动复用。反馈绑定生成补丁的版本；旧版本保留既有复用资格。单个游戏失败只排除该游戏的匹配。

“有问题，继续修复”保存问题并打开修复配置。新版验收和提取保存成功后保留旧版；确认当前补丁“效果正常”后，清理同一适配器中早于已确认版本的历史版本，以及修复链中的旧版。其他项目仍在使用的版本保留，有任务运行时延后至任务结束清理。清理版本文件和关联记录，保留项目文本、译文及补丁。修复中断可继续。

## 进度与继续

进展区显示当前问题、最近突破与实现进展，不额外调用模型汇报。模型说明、资源验收和游戏运行结果分别展示。

暂停、预算耗尽或重启后可继续已有会话。新增要求会取消尚未执行的旧调用；切换模型或协议时保留文件和进度摘要，重建协议会话。等待信息或无法继续时显示具体原因，未通过验收不会发布。

会话、源码和样本保存在项目 `adaptation/current/`，保留与清理规则见[产物约定](artifacts.md)。
