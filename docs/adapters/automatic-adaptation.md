# 识别与智能适配

## 两个入口

项目顶部的“常规识别”（已有适配器时显示“重新识别”）使用已有适配器探测引擎、资源格式和版本，提取其支持的文本，不调用分析 API，也不会扩展解析范围。未匹配时显示“未找到可用适配器”。

“智能识别与适配”使用项目选择的分析 API 调查游戏，并开发或组合解析、回填工具。已有适配器无法处理某个引擎版本时，也可以使用此入口。在“全局 → API 与任务默认值”设置默认分析 API、Token 预算和模型轮数，初始预算为 1,000,000 Token（1M）、60 轮；达到上限后可继续已有任务。新项目跟随全局默认，已有独立设置保留。项目设置和开始／继续适配弹窗均可取消“使用全局默认”并单独调整，或重新勾选以恢复跟随。独立预算在关闭弹窗或重启程序后沿用；输入无效时保留此前设置。

分析服务必须支持所选协议的函数工具调用。支持普通聊天或翻译并不代表支持智能适配。Chat Completions 和 Responses 使用各自的工具调用协议；程序不会将模型文本中的“命令”直接当作工具执行。

已有适配进度或可用适配器时，按钮显示“继续智能适配”。发现菜单、物品或其他文字仍为原文时，使用此入口，并在补充要求中说明遗漏的位置。程序继续已有源码和调查结论；适配成功后自动重新提取文本，已提交且仍兼容的译文继续复用，无需删除项目或重新开始翻译。

弹窗中的“本次目标”随适配会话保存，继续任务和压缩对话后仍沿用。“修复现有问题”用于编码、字体、启动或回填失败，保留已有提取范围和译文匹配字段，完成相关验收后先交付试译；“补全遗漏文字”用于扩展文字覆盖；“识别并建立适配”用于尚无可用方案的游戏。需要改变目标时可在同一弹窗切换，已有源码和调查记录保留。

智能适配面向玩家可见文字，包括剧情、菜单、界面、物品、装备、技能、教程和提示。图片或视频内文字、内部标识、资源路径和程序逻辑不在提取范围。模型会结合实际资源调查文字类别，并在支持范围与注意事项中说明已知遗漏。翻译完成数只统计已提取的文本；资源校验通过不代表整款游戏的文字都已覆盖。

继续完善已有适配器时，使用独立定位的原文样本核对提取结果。`checkpoint` 和 `test_adapter` 接受 `coverageSamples`（资源路径、字段定位、原文），程序逐项检查，可发现读写双方共同使用错误字段偏移的问题。修复任务已有提取记录时，程序直接核对原有文本的 ID、位置、原文、上下文、说话人、类型和保护标记，防止修复让译文或校对记录失效；智能体通过 `inspect_existing_text` 按需分页查看字段，全量记录留在本地。

`pendingCoverage` 保存已确认的漏提文字；`runtimeChecks` 单独保存需要进入游戏验证的启动或显示事项，不作为文字覆盖缺口。省略参数不会清除记录，压缩对话和重启后仍保留。修复任务可以披露其他范围的已知遗漏后完成，无需自动扩展到所有文字类别。记录有数量与长度限制，不另建数据库或逐条文件。

有已知待办时，发布必须明确选择部分支持（`finish.allowPartial=true`）并说明原因，结果仍显示未覆盖项。独立样本核对、资源往返和游戏实际显示是不同的验证范围；有限样本不能证明全游戏文字已完整提取。只有样本或源码等验证输入变化才需重新验证，单纯整理待办不会触发重新编译。

## 智能体能做什么

- 查看文件目录、大小、文件头，按偏移读取大文件片段或搜索字符串。
- 自动读取系统 ANSI 代码页、每个 EXE 的转区配置、少量启动脚本及错误日志摘要；`inspect_game_launch` 可刷新这些证据，`find_game_file` 可核对报错中提到的文件是否存在。
- 按引擎或格式查询研究资料，检索公开 GitHub 仓库，按关键词或位置读取 HTTPS 文档，下载必要工具。
- 编写和修改多个 C# 源文件，运行本地工具，查看编译或解析错误后继续修改。
- 使用 `run_csharp` 直接编译运行临时 C# 探针，支持本地 DLL、命令参数和标准输入，无需创建工程或安装 SDK。
- 使用 `inspect_unity_schema` 按类型查询 IL2CPP v31 元数据或托管/dummy DLL 的字段、父类、关联结构及 Description/Tooltip 等文本方法线索，无需编写扫描脚本。不能确定的数组或泛型类型会明确标为未解析；字段声明不等同于 Unity 资源中的序列化布局，仍需真实样本验证，方法名称也不证明其实际显示用途。
- 装备或特质有名称但缺少直接描述时，沿效果引用、状态效果和提示生成方法检查文字来源，区分序列化字段与动态文本模板。元数据字符串表中的资源路径、查找键和调试信息不参与翻译；模板的自定义替换标记需结合调用方确认并保留。已知遗漏单独记录，资源回填校验不代替覆盖范围检查。
- 使用宿主提供的检查验证提取、原文回填和中文写入，验证通过后保存适配器。

仅必要的资源片段、资料和工具结果进入模型上下文，不默认上传完整游戏。资源文件本身没有 64 KB 采样门槛；单次读取和工具输出有大小限制。公开资料检索受网站访问条件和匿名请求配额限制，不需要另配搜索 API。

工作区 `work/` 下的文本报告默认按 UTF-8 读取，原始游戏未知格式文件仍默认按二进制读取。搜索结果提供可用的字节位置，便于只读取相关函数或字段。上下文按大小保留近期工具结果；压缩摘要保留当前实现所需的布局结论和下一步，已读取的适配器协议继续可见。

通过验证后，读取文件、运行分析工具或更新 `work/` 笔记不会单独取消验证。发布前会检查源码、依赖、资源和已构建包的内容；存在变化时需重新验收。异常中断的工具操作仍按结果未确认处理。

适配器按引擎或资源模板命名。现有工具可用时保留工具和必要调用代码；缺少功能时补充解析实现。新包根据资源规则发现当前游戏的文件，不绑定首款游戏的文件名。下载依赖记录来源和文件指纹，模型需要核实版本、格式支持和使用许可。

## 复用内置脚本解析器

智能适配开始时，程序先通过有界的目录与文件头检查，给出相关的[内置解析器](vntextpatch.md)候选、资源样本及待验证环节。文件后缀与容器签名只是线索，不能证明包内脚本兼容；普通 DAT、TXT 等文件不会仅凭后缀认定引擎。常规识别中已有的内置解析结果也会传给智能体。

智能体可以用 `list_adapters` 检索内置和已发布的能力，用 `inspect_builtin_adapter` 查看相关解析器的限制、调用说明及指定源码片段。`try_builtin_adapter` 直接处理工作副本中的少量脚本，不需要先生成调用程序：每次最多 12 个文件、合计 64 MiB，返回提取数量、少量文本预览、具体解析错误，以及默认执行的原文逐字节回填检查。伴随文件也应纳入样本。这个限制只约束开发阶段的快速试验，不限制正式任务规模。

解析器兼容时，`copy_adapter` 默认只写入调用代码和固定版本依赖清单，VNTextPatch DLL 与许可文件按内容哈希跨项目共享，智能体补充资源包、格式变体或中文运行支持。需要修改解析实现时可选择源码模式，只复制所选引擎组及公共工具，已有不同内容的源码不会被覆盖。生成适配器的探测仍只读取文件头，完整脚本解析用于提取、回填和结构验证。

候选线索及最近样本试验保存在现有 `session.json`，包含观察时间和试验输入哈希；继续适配和压缩上下文后仍可使用，不另建逐次报告。资源变化后可通过 `list_adapters` 的 `refreshCandidates` 刷新线索，必要时重新试验。样本检查不替代完整 `test_adapter` 验收，也不代表中文字体或游戏启动已经验证。

需要中文编码、字体或启动处理时，智能体还可查询 `list_adapters.components`，通过 `inspect_adapter_component` 确认接口与限制，再用 `copy_adapter_components` 直接复制所需实现。现有组件包括 CP932 字符映射、QLIE 字体与独立转区启动器、System4 FNL 位图字形。启动器自带编译好的 EXE，普通源码直接参加适配器编译；详见[编码与运行组件](components.md)。

## 引擎研究资料

`search_engine_references` 按引擎名称、别名或脚本格式检索 [GalTransl-GalGameReverse-Skill](https://github.com/GalTransl/GalTransl-GalGameReverse-Skill) 的索引，返回文档、模块、公开函数和适用范围。已有共享工具库时直接查询本地固定版本，否则读取在线索引。索引条目不代表本工具已支持该引擎，也不代表该游戏验证通过。

`inspect_engine_reference` 按精确引擎 ID 读取指南，支持按路径、关键词和字符范围读取所需 API。发行包附带固定 commit 的工具库，将 Python 源码、目录、指南和许可文件保留在一个共享 ZIP 中。`run_engine_python` 自动提供便携 Python，直接运行 `work/*.py` 或 `src/tools/*.py` 连接脚本，复用 `python.archives` / `python.engines`，无需将已有算法重新实现为 C#。不同引擎和版本的函数接口不统一，仍需按指南选择并用样本验证。

`use_engine_reference` 将固定依赖记录与 C# 调用桥写入适配器源码。智能体只需补 JSON CLI、资源选择及确实缺失的版本处理，再执行原有 `test_adapter`。发布后的适配器使用相同共享库，常规提取与回填不调用模型。继续适配保留所用源码版本，已安装的库可离线使用；工具缺失时需恢复对应版本的完整发行包或共享工具，内容改变会明确报错，不自动替换成新版。

标准发行包的工具位于 `<应用目录>/tools/engine-tools`，直接读取；已有固定版本可保留在 `<数据目录>/extensions/engine-tools`。VNTextPatch 共享副本位于后者的 `vntextpatch/<内容哈希>`，每个版本只保存一次。它们不复制到每个项目或游戏目录。打包阶段准备 GalTransl 与 Python，缺失则打包失败；正常智能适配不会自动下载这些内置依赖。模型确需额外工具时仍可使用 `download_tool`，进度显示文件名、来源、用途和保存路径；临时分析文件不自动成为发布依赖。Python 不安装到系统，不使用 pip，不生成项目 `__pycache__`。可选第三方模块（如部分格式需要的 `zstandard`）不包含在便携标准库内；模块需要外部数据文件或原生库时也必须单独核对，不能将参考代码数量当成完整引擎支持数量。

未命中时可继续查询格式目录和上游注册清单。`fetch_url` 支持 `query` 关键词定位及 `offset` / `length` 字符分页，大型目录在本地搜索，只将相关片段交给模型；读取完整条目后再判断能力。GitHub 仓库搜索只查仓库元数据，不查源码正文。Bishop 的 GSC 资料与 BSScript Rev.6 等不同格式不能因厂商相同而直接混用。

其他在线资料通过 `fetch_url` 按需读取，每份上限 8 MiB；超限明确报错，不将截断结果当成完整目录。返回值包含读取时间、内容哈希及后续阅读位置；单次适配在内存中最多缓存 4 份、合计 12M 字符。在线 `main` 资料可能更新，与已固定共享版本不同；开发应优先读取实际调用版本的本地指南和源码。访问失败不代表格式不支持。

智能体按容器、解码、文本语义、回填、重封包和运行显示分别定位缺口。缺少 writer 或尚未实现已有格式规则时，继续处理当前缺口；未找到现成仓库不能作为停止分析的唯一依据。资料中的目录约定不会覆盖本应用的项目存储方式。复用源码时需核对文件许可并保留声明和源码义务；工具库保留相应源码与通知，不自动部署 UIF、字体或运行时注入 DLL。

## 验证与产物

完整适配要求实际提取成功、原文逐字节回填、不同中文修改后重新提取、部分试译时其余文本保持原样、文本身份稳定以及输出路径检查通过。仅识别引擎或提取文本不能激活为完整适配器。资源检查通过也不代表已经验证游戏启动、字体、换行、分支或存档。

部分试译验收仅提交少量译文，重新提取生成的实际资源，核对修改项及所有未修改项；适配器不能因缺少某条译文而丢弃或改变原文。字符映射需要避开整个补丁中保留的日文、姓名和界面字，真实中文仍保存在译文缓存中。这项资源检查不替代原引擎的字形和码位兼容性验证。

继续开发任务时，若保存的验证结果早于当前验收规则，发布前会要求对现有源码重新验收；已有源码、译文和调查进度继续保留。

`test_adapter` 先比较真实游戏与暂存样本的探测结果，报告缺少或多出的必需文件及启动入口差异，再执行完整验收。`discoveryOnly=true` 可提前检查探测逻辑，但不会授予发布资格。探测从每个文件前 64KB 开始；需要包尾、索引或 PE 资源时，适配器通过 `probeReads` 请求有限片段，由宿主在本地提供后再次调用探测。最多追加 4 轮、64 个片段，每片段不超过 1MiB，总量不超过 8MiB。索引读取不需要复制完整媒体封包，也不调用模型。

开发先验证代表性文本的提取和原文回填，并将可用解析代码保存在 `src/`；再验证少量中文的编码与字形路径，随后扩展覆盖范围。字体或程序分析围绕具体失败展开，已有探针和结果用于继续调查。

适配器可输出汉化资源和必要的新 EXE；启动程序需要通过静态结构检查。适配完成后，使用“选择文本试译”选择能在游戏中定位的片段，再生成并安装补丁进行实际验证。

适配时需检查原有启动方式和区域设置配置，例如 `*.exe.le.config`。脚本文本编码与原生进程处理日文文件名、视频路径、标题和界面的 ANSI 代码页是不同要求，`chcp` 或 .NET 文化设置不能替代原有转区方式。新增启动器或修改 EXE 时，应保留原有转区入口、配置和工作目录；独立字形探针不能证明游戏启动及资源路径正常。

补丁需要启动器时，应生成独立 EXE，并在 `build.launchExecutable` 中声明相对路径，供安装后显示正确入口；留空会沿用原启动入口。启动器临时注册的字体须保持到实际游戏进程退出，不能因转区中间程序提前结束而卸载。

程序会拒绝新增 EXE、CMD、BAT 或 PowerShell 文件却未声明 EXE 启动入口的产物。所选 EXE 已有的 `.le.config` 必须纳入资源验证，中文回填不得修改原转区配置。启动环境摘要保存在现有会话状态中，继续分析和压缩上下文后仍会提供；这些本地检查不额外调用模型，也不启动游戏。

“文件或视频不存在”的报错应先核对实际文件、原脚本引用字节、工作目录和转区环境。字体显示异常还需检查游戏是否重置了字体配置。上述静态检查能发现遗漏，不能证明启动器实际传递了正确的运行环境；游戏运行结果仍单独标记为尚未验证。

适配器包保留必要源码、编译程序、工具依赖和描述信息，保存到共享扩展目录。`test_adapter` 默认复用持久化的发布清单，可用 `update_release_files` 增删条目，或传入 `releaseFiles` 整体替换。每项记录 `source`、`runtime`、`asset` 或 `license` 角色及用途；宿主只编译、验收和发布这份文件集合，分析探针、样本和报告留在工作区。路径和示例见[正式适配器发布约定](artifacts.md#正式适配器)。项目固定使用经过验证的版本；开发失败不会替换已激活版本。后续游戏可以通过常规识别复用，不需要再次调用智能体。

玩家需要的是汉化资源和启动程序，安装后的游戏不依赖适配器、模型服务或本工具。

## 保存与继续

正式适配器、汉化运行文件、分析脚本、验证临时目录和日志的分类，以及哪些文件参与发布、何时保留或删除，见[引擎分析产物与目录约定](artifacts.md)。

每个项目只有一个当前开发目录：

    adaptation/current/
      session.json   当前会话、工具进度、Token 用量和已确认结论
      src/           当前源码及所需工具
      resources/     选择用于本地分析和验证的原资源副本
      work/          需要继续使用的分析输出
      build/         当前编译结果

目录按需创建。源码修改直接保存到当前版本，不为每轮尝试另建目录或 .bak。会话状态原子写入；执行结果已经保存的步骤不会在继续时重新执行。进程被中断且结果未确认时，智能体先检查现有文件。

“继续适配”保留代码和上下文，并使用新的本次预算。Token 预算和模型轮数采用当前全局默认或项目独立设置；任一耗尽时暂停，并说明触发了哪项上限。修改全局默认只影响跟随的项目的后续任务，运行中的预算不变。切换分析模型或协议后会重新建立会话，保留现有文件及已确认的进度摘要。会话较长时，智能体可保存进度摘要并缩短上下文。状态文件损坏时仍可根据现有源码重新分析。

未完成的项目直接显示“继续适配”。点击后可以填写补充要求、工具线索或游戏运行反馈；新要求会提交给智能体，并取消尚未执行的旧工具调用，让它重新决定下一步。重启程序后仍会显示保存的卡点与后续操作，技术总结可在“查看适配详情”中展开。

“翻译任务”中的“适配进展”显示模型对关键问题的简短说明：仍在探索什么、取得了什么突破，或方案已确定后正在实现和验证什么。说明随正常分析响应可选更新，没有百分比，也不为获取进展额外调用 API。普通文件读取和工具执行不会覆盖这段说明；没有新说明时保留原文和更新时间。

最近一次突破会保留在当前说明下方。模型发现旧结论被新证据推翻时，可以明确更正并撤回此前突破。最新说明和最近突破保存在同一份 `session.json` 中，重启、切换项目及继续适配后恢复。它们属于模型说明；能否生成试译产物仍由实际验证和发布结果决定，不能据此认定游戏内显示已验证。

继续时跳过初次适配器匹配，向模型提供现有源码清单、已准备的资源、最近验证结果和已有调查笔记，直接处理未完成步骤。切换模型后也会提供这份进度快照。长会话会提示智能体调用 `checkpoint` 保存已确认结论、排除的方案和下一步，再缩短上下文；快照和摘要仍保存在同一份会话文件中。

压缩阈值按可见内容计算，不把 JSON 转义开销或 Responses 的加密推理内容当作待总结文本。后续调用需要的原始推理数据仍随当前会话保留。摘要记录结论和证据文件位置，详细源码和分析输出留在已有文件中。

相互独立的读取和查询可以在一次模型响应中提交多个调用。也可以提交最多 8 项按顺序执行的 `write_file`，最后一项可为一次 `run_csharp`、`run_engine_python` 或 `run_tool`，省去写完再请求模型决定运行的往返。每项结果单独持久化；前置操作失败或中断且结果未确认时，后续步骤标记为未执行，交由模型核对后重试。已成功提交的写入可从下一步继续。暂存、依赖复制、验收、发布和 `checkpoint` 仍需单独调用。

请求保持最新一轮工具结果完整，其他成功结果按 64KiB 预算从近到远保留；不再只因经过三轮就缩短结果。超过预算或重复的大结果发送索引和短预览，重复结果注明仍可见的相同副本；失败信息保持完整。原始结果仍在 `session.json` 中，可通过 `read_tool_result` 按范围或关键词读回，不需要重新执行工具，也不另建结果文件。

发送的可见历史超过 192KiB，或保留的历史超过 768KiB 时，请求模型调用 `checkpoint` 保存结论后压缩；不因小消息数量单独触发。压缩后保留最近最多四轮完整工具交互（合计不超过 64KiB），并列出最近修改的主源码和分析报告。摘要优先控制在 3000 字内，保留当前实现需要的字段顺序、数组步长、接口约定和覆盖遗漏，直接继续下一项操作；完整源码和证据仍引用已有文件。已经读取的适配器协议也会随压缩和恢复快照提供。

常驻提示集中于通用协议、实现目标及验证要求，引擎和组件的详细规则按需读取。连续 24 轮没有观察到源码写入、组件复用或完整验收通过时，在下一次正常请求中提醒模型核对现有成果，优先完成可验证的实现步骤。计数保存在现有会话中，压缩或继续不会重置；相同内容的源码写入不会重置计数。这只是收敛提醒，不判定研究无效、不自动终止任务，也不额外调用模型；外部工具直接修改源码时可能仍会出现提醒。恢复较长的旧会话时也会先核对一次。资源验证与实际游戏运行验证始终分开，不能为节省 Token 降低回填验收要求。

耗时日志区分发送的可见历史大小、保留历史大小和被缩短的工具结果数量，Token 用量仍采用 API 返回值，便于比较实际输入开销。

编码、字体或回填验证失败时，智能体应继续调查和修改。只返回阶段总结时，程序会要求它继续执行工具；连续两轮只给总结则停止，保留进度并提示继续或更换分析 API。所有继续操作仍受本次 Token 和轮数预算限制。

确实需要用户提供信息或操作时，界面显示“适配需要补充信息或操作”，并说明具体需求。调查后判断现有方案无法完成时，显示“当前方案无法完成适配”，保留原因和可尝试的下一步。这两种情况均不会发布未通过验证的适配器。

模型报告无法适配时，还须说明是否存在本地可执行的后续工作，并提供具体尝试、结果及证据位置。存在后续步骤或说明缺失时，程序要求继续执行；连续两次只请求停止、没有开展其他工作时，按“适配未完成”暂停并保存下一步，避免无限重复。此判定约束模型提交的停止说明，不代表程序能独立证明某引擎不可支持。编码限制、未完成的字体分析、缺少现成解析器或搜索无结果本身不足以作出无法适配的结论。

需要完全重来时，停止任务后手动删除该项目的 adaptation/current。这不删除译文缓存或已发布适配器。程序不会扫描清理历史开发目录。

## 本地执行

完整发行包包含固定 .NET 工具链。编译使用框架引用和宿主编译参数；可执行 C# 封装的工具依赖，不需要模型提交 MSBuild 工程或安装系统组件。

临时 C# 分析入口放在 `work/`，通过 `run_csharp` 使用自带的 .NET 10 编译运行。`sourceFiles` 可同时列出 `work/` 测试入口和 `src/` 中已有解析代码，无需复制；只编译明确列出的文件，不自动包含其他 `Program.cs`。可显式引用 `work/` 或 `src/tools/` 下的 DLL；工具返回编译诊断、退出码及 UTF-8 输出。临时编译产物在本次执行结束后移除，源码和分析结果保留；测试入口不会参与适配器发布。Windows PowerShell 5.1 可用于文件与工具编排，其 `Add-Type` 不提供现代 .NET 编译环境。

`inspect_pe_imports` 直接读取 EXE/DLL 的普通 PE 导入表，支持按函数名或 DLL 名筛选、分页，并返回 IAT 地址、文件偏移和 x86/x64 间接调用／跳转的候选字节位置。每页默认 20 项、最多 40 项；过大的正整数页大小会收窄至 40 项，通过 `nextOffset` 继续读取。参数协议声明范围，数值错误会说明收到的值和允许范围。它不运行游戏、不下载工具，也不生成文件。候选位置尚未确认指令边界和运行可达性，动态解析、延迟导入及其他寻址方式可能遗漏；可用这些位置缩小后续反汇编范围，不能据此认定中文显示通过。BSScript Rev.6 按文件头识别并提供专用调查指引，不能直接套用 Bishop GSC 或 KaGuYa 的脚本解析器。

`inspect_pe_code` 使用随程序附带的 Capstone 5.0.6，在一次调用中反汇编 1–8 个已知代码范围。Windows x64 宿主可分析 x86/x64 游戏，无需准备 Python、下载反汇编器或编写地址专用脚本。地址通过 `addressKind=va/rva/file` 明确区分首选映像地址、相对虚拟地址和文件偏移；工具按 PE 节表换算，不假设 RVA 等于文件偏移。结果包括指令字节、三类地址、直接分支目标及继续读取地址。

每段最多 4096 字节、合计最多 16384 字节，每段默认 80 条、最多 200 条指令；单段地址错误不会丢弃其他段的结果。工具从指定起点线性解码，起点仍需调用目标等证据支持，解码成功不代表代码可达或实际运行过。合成字节反例应再对照实际游戏缓冲的来源与处理路径，不能仅因任意拼接可能出错就无限扩大调查范围。许可证随反汇编库一同发布，库在首次加载时校验固定哈希。

工具以当前用户权限运行普通本地进程，不使用 AppContainer。宿主对路径、执行时间和输出进行检查，取消时终止进程；这些检查不构成操作系统级隔离。原游戏通过内置读取操作调查，开发工具使用选择的资源副本。

同一游戏同时执行一个任务。智能适配同时运行一个游戏，与其他游戏的常规识别和翻译分别调度；同一 API 按单次模型请求排队，本地编译期间释放 API 名额。

项目的 `logs/adaptation-yyyyMMdd.jsonl` 记录每轮 API 和工具耗时、分析思考等级、上下文大小、Token 用量及执行状态。API 耗时包含网络与服务端处理，另记本地 API 队列等待时间，不能将其直接视为模型思考时间。每天追加到同一个文件，不复制成功请求、响应或工具正文；工具失败时记录简短诊断，详细 API 异常沿用 `api-*.json` 日志。

日志按 `runId` 区分每次开始或继续，记录程序构建标识、实际模型名称、预算以及常驻提示和工具定义的字节数。工具条目包含调用 ID、参数指纹、文件路径／读取范围等定位字段和精简结果；不保存源码写入内容、查询正文、命令行或标准输入。公开资料 URL 去掉凭据、查询参数和片段。验证失败保留具体原因，验证耗时分为编译、识别和回填验收，避免后续会话压缩后失去诊断。

开发者可运行 `scripts/analyze-adaptation-log.ps1 -ProjectDirectory <项目目录>`，只读汇总每次运行的模型／工具耗时、Token、轮数上限、源码／探针／笔记写入、参数失败及最近完整验收之后的消耗。参数重复是调查线索，必须结合输入文件是否改变及上次结果判断，不能直接视为无效工作。源码写入统计仅覆盖 `write_file`，外部工具也可能修改源码。旧日志缺少的定位信息不会反推或伪造。

CLI 约定见[适配器协议](../../contracts/adapter-v1.md)，模型接口见[配置说明](../model-providers.md)。
