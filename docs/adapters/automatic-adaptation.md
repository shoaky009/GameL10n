# 识别与智能适配

常规识别使用已有适配器；智能适配在现有能力不足时调用分析模型，调查资源并开发解析和回填能力。日常操作提示在对应界面中，本页说明支持范围、费用来源与结果的含义。

## 选择适配目标

| 情况 | 入口与目标 | 结果 |
| --- | --- | --- |
| 检查已有支持 | “常规识别”，已有适配器时显示“重新识别” | 提取已支持的文本，不调用分析 API，不扩展解析范围 |
| 没有可用适配器 | “智能识别与适配”中的“识别并建立适配” | 调查资源格式，建立并验证适配器 |
| 编码、字体、启动或回填失败 | “继续智能适配”中的“修复现有问题” | 保留原有文本身份和译文匹配字段，优先修复当前问题 |
| 菜单、物品等文字仍未提取 | “继续智能适配”中的“补全遗漏文字” | 扩展覆盖范围，完成后重新提取，复用仍兼容的译文 |

补充要求中可以说明遗漏文字出现的位置、启动方式和实际报错。目标随会话保存，继续任务时可调整；已有源码和调查记录保留。

适配范围包括剧情、菜单、界面、物品、装备、技能、教程和提示中的玩家可见文字。图片或视频内文字、内部标识、资源路径和程序逻辑不在提取范围。翻译完成数只统计已经提取的文本，不能据此判断整款游戏的文字已全部覆盖。

## 模型与预算

分析 API 必须支持所选协议的函数工具调用，仅支持普通聊天或翻译的服务无法用于智能适配。配置方式见[模型接口配置](../model-providers.md)。

新项目使用全局默认分析 API、Token 预算和模型轮数，默认预算为 1M Token、60 轮。项目设置和开始／继续适配弹窗可以改为独立设置。任一上限达到后暂停并保存进度；继续时使用新的本次预算，运行中的任务不随全局设置变化。

工具定义按需提供，已有结果和已验证的相同输入尽量复用。首次新建适配时，程序先在本地试用候选脚本，并检查现有组件能否直接处理完整资源。纯裸 `.rpy`、纯裸 `.ks` 或明确适用的 RPA3 + Ren’Py 源码组合，可以自动完成全部匹配资源的验收与发布，本次不发出模型请求、不消耗分析 Token。其他情况将已准备的资源、源码和具体失败交给模型继续处理；补充要求、修复、覆盖扩展及恢复中的会话仍沿用原有模型流程。分析 API 的配置要求不变。

自动组合仍须通过完整提取与中文回填验收。编译脚本、混用格式、XP3 过滤器不明、已知启动问题或检查超出预算时，不会仅凭少量样本成功完成任务。自动发布只确认模板选中的源脚本范围；没有独立样本时，文字覆盖仍未评估，游戏内中文显示仍需实际验证。长会话会压缩参与请求的历史，并保留原始记录供后续查回。这些措施减少重复调用，但不保证某个预算内一定完成适配。

## 本地工具、联网与下载

完整发行包附带固定版本的 .NET 工具链、VNTextPatch、Siglus 工具、Capstone、共享引擎工具库和便携 Python。常规智能适配直接复用这些工具，不自动下载缺失的内置依赖；缺失时需恢复对应版本的完整发行包或共享工具。Python 不安装到系统，不要求用户运行 pip。

模型可以检索公开引擎资料和 GitHub 仓库，并下载当前格式确实需要的额外工具。进度显示下载文件、来源、用途和保存路径。额外工具与资料按 URL 和内容哈希缓存，跨项目和重启复用；项目已经固定的工具版本不会随其他项目更新而替换。缓存位置及清理影响见[产物与目录约定](artifacts.md)。

参考库包含某个引擎的代码，不代表该引擎已完整适配。某些格式还需要额外模块、私有格式处理、字体或启动兼容工作；搜索失败也不能直接说明引擎不受支持。内置脚本范围见[脚本解析器](engines/vntextpatch.md)，现成封包能力见[封包组件](engine-components.md)。

只有必要的资源片段、资料和工具结果进入模型上下文，不默认上传完整游戏；其中可能包含游戏文本。分析工具以当前用户权限运行本地进程，路径、执行时间和输出限制不构成操作系统级隔离。开发与验收使用资源副本，安装补丁是独立操作。

## 验证与产物

适配器发布前需要通过实际提取、原文逐字节回填、完整与部分中文回填、重新提取、文本身份和输出路径等检查。修复任务还会对照已有提取记录，避免原有译文和校对记录失去匹配。源码、依赖或资源变化后，需要重新验收。

| 检查结果 | 能说明什么 | 仍需确认什么 |
| --- | --- | --- |
| 候选或少量样本通过 | 当前样本可能适用某个解析器 | 完整资源、其他文本类别和格式变体 |
| 资源验收通过 | 受支持范围内的提取与回填满足当前检查 | 游戏启动、中文显示、换行、分支和存档 |
| 部分支持 | 已验证的范围可用，同时保留已知遗漏 | 未覆盖文字和待确认的运行问题 |
| 游戏运行验证记录 | 用户检查过当前补丁的实际表现 | 其他资源版本或重新生成的补丁 |

资源验收通过后，选择能在游戏中找到的少量文本试译，安装补丁并进入游戏确认。需要转区的游戏沿用原来的启动环境；补丁生成独立中文启动程序时，使用界面显示的入口。

正式适配器保存到共享扩展目录，项目固定使用经过验证的版本。开发失败不会替换已激活版本；后续符合条件的项目可以通过常规识别复用。玩家运行汉化后的游戏只需要补丁文件和必要启动程序，不依赖模型服务或本工具。

## 进度与继续

“适配进展”显示当前问题、最近突破及实现进展；任务状态和实时日志显示每次调用的工具名。这些说明不额外请求分析 API，也不能代替资源验收或游戏运行结果。

暂停、预算耗尽或重启后，可以继续已有会话。补充的新要求会取消尚未执行的旧调用，让模型依据新信息决定下一步。切换模型或协议后，程序保留文件和已确认的进度摘要，重新建立对应协议的会话。

需要用户提供信息时，界面显示具体需求；当前方案无法继续时保留原因和后续建议。未通过验证的适配器不会因此发布。连续只给总结、没有执行工作的会话也会暂停并保留进度。

开发资料保存在项目的 `adaptation/current/`，包含会话、源码、样本和分析结果。重新分析、备份或清理前先查看[产物与目录约定](artifacts.md)，避免丢失续作所需资料。排查请求、缓存、验收和恢复逻辑见开发者文档[执行与恢复机制](adaptation-internals.md)。
