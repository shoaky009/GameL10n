# 自动适配

自动适配用于没有匹配引擎或资源模板的游戏。工具先检索本地已发布能力，包括为其他游戏建立的模板；跨游戏复用需要对当前资源重新进行回填验证，不调用模型开发代码。

## 样本与生成范围

需要新能力时，用户确认将最多 4 个资源样本发送到配置的模型服务，每个不超过 64 KB，总计不超过 128 KB。不会默认上传完整游戏。最多尝试 2 次，适配预算为 16,000 Token，开发 Token 与翻译 Token 分开统计。

模型只能提供带引擎／模板分类的单文件 C# 程序，不能提交项目文件、构建脚本、NuGet 依赖或任意宿主命令。代码型扩展使用[版本化 JSON CLI 协议](../../contracts/adapter-v1.md)。

生成式扩展只处理批准资源集合，不生成游戏启动器或修改可执行文件。资源文件名也属于该版本的处理范围；不能据此推断对其他文件名、复杂二进制容器或整部游戏的支持。

## 验证与版本

发布要求原文回填逐字节一致、重复提取稳定、替换为不同中文文本后可重新提取、输出文件边界和完整性检查通过。样本通过只记为样本兼容；汉化产物的结构校验与游戏运行验证分别记录。

包按引擎／模板标识保存，源码和资源范围的指纹作为版本号。每款游戏固定使用经过验证的版本，保留之前版本用于回滚。其他游戏检索到该能力后仍需独立验证，不能仅依据模型声明激活。

## 执行要求与限制

编译和执行依赖固定的 .NET 工具链及 Windows LPAC AppContainer，配合 Job Object 限制进程、内存和执行时间，不授予网络能力。系统无法建立隔离时，在发送样本和调用模型前结束任务，不降级为普通进程。

独立进程本身不等于安全沙箱。应用没有磁盘硬配额；自动校验也不能证明游戏运行兼容或任意生成代码的完全安全。完整发行包需要包含 `toolchain` 目录。

失败后保留工作区诊断，既有适配能力与其他汉化任务继续可用。工作区及未发布扩展不随汉化补丁安装到游戏目录。
