# 引擎识别声明

## 识别流程

`Application::recognize` 扫描目录，从引擎索引筛选文件规则、读取必要签名，再执行候选 CLI `probe`。匹配后保存原文工作资源，提取文本、校验身份并检查原文字节回填。

格式不兼容时尝试下一候选，无可用候选或提取不足时转入智能适配。扫描和失败证据在阶段间复用。取消、工具缺失、文件访问、超时及提交错误直接报错，不作为格式不兼容交给模型。

已发布适配器的常规复用不重复执行开发阶段的全量中文模拟回填。实际生成补丁仍校验本次译文和输出。界面入口见[识别与智能适配](automatic-adaptation.md#选择适配目标)。

添加和打开游戏只读取项目资料，不执行适配器恢复。显式识别时，优先查询相同项目 ID 的资源验收通过记录，按最近使用时间尝试对应发布版本，即使该版本仍待游戏运行验证。探测、包完整性、提取和原文回填检查仍须通过；本地提取成功后不因文本数量较少而再次触发智能适配。历史版本均不适用时再检查其他常规候选和内置解析器，失败原因保留在识别诊断中。

重新添加游戏保留已有提取、译文和校对数据；文本数据已删除时，通过识别重新提取，优先复用已有实现。缺少提取结果时，即使项目残留未完成的智能会话，也先检查该游戏的历史版本；本地恢复失败后再续接会话。已有提取结果的未完成会话继续原适配任务，强制智能识别仍遵守其显式选择。

这项资格仅用于原游戏，其他游戏仍须满足发布版本的运行验证门槛。已停用、删除、排除或对该游戏记录失败的版本不会自动找回，固定版本的既有启停规则保持一致。

## 包清单

`package.json` 可选的 `recognition` 声明静态匹配条件：

| 声明 | 用途 |
| --- | --- |
| `resourcePatterns` | 资源选择模式的并集，不要求每个模式命中 |
| `recognition.required` | 全部须满足的必要条件 |
| `recognition.hints` | 仅影响排序的辅助证据 |
| CLI `probe` | 解析结构并确认匹配及必需资源 |

以下示例要求存在至少一个长度不小于 16 字节、以 `PACK` 开头的 PAK 或 ARC 文件：

```json
{
  "schemaVersion": 1,
  "required": [{
    "patterns": ["**/*.pak", "**/*.arc"],
    "minimumSize": 16,
    "signatures": [{ "origin": "start", "offset": 0, "hex": "5041434B" }]
  }],
  "hints": [{ "patterns": ["engine.ini"] }]
}
```

同一规则的路径模式取任一匹配，大小和全部签名须由同一个文件满足。路径相对游戏根目录，使用 `/`，忽略大小写，支持 `*`、`?` 和 `**`；`**/` 可匹配根目录。

| 字段 | 约束 |
| --- | --- |
| `schemaVersion` | `1` |
| `required`、`hints` | 必填，可为空，合计最多 32 条 |
| `patterns` | 每条 1～16 个，禁止绝对路径和目录穿越 |
| `minimumSize`、`maximumSize` | 可选，非负字节数，包含边界 |
| `signatures` | 可选，每条最多 8 个，全部须匹配 |
| `hex` | 1～64 字节，连续偶数长度十六进制 |
| `origin` | 默认 `start`，也可为 `end` |
| `offset` | 非负；`start` 从文件头到签名起点，`end` 从文件尾到签名终点，`end:0` 匹配末尾 |

必要条件应来自格式证据，不使用游戏标题、安装路径或整包哈希。声明不包含可执行脚本或主程序调度参数。

## 发布与兼容

`test_adapter` 提供 `recognition` 时替换声明，省略时复用，空数组可清空条件。必要条件须在真实资源上确认；声明参与包版本指纹。

匹配结果分为匹配、不匹配和未知。无声明、未知版本、不可读或检查预算不足时保留未知并继续 CLI 探测，只有已确认不满足的必要条件才排除候选。声明版本独立于 CLI 和发布清单。

## 主程序索引与执行

`extensions/library-index.json` 保存展示和筛选摘要，执行候选前才加载包并校验完整性。索引缺失时从注册元数据重建。

每次显式识别使用独立扫描缓存，结束后释放：签名与文件头最多 8 MiB、512 次读取；每条规则最多检查 128 个文件，其余保留未知。外置候选共用 45 秒 `probe` 执行预算，资源哈希、提取和回填按各自超时控制。

## 常规识别日志

在项目当天的 `logs/yyyyMMdd.log` 搜索 `[识别诊断]`，按 `runId` 区分任务。

| 事件 | 内容 |
| --- | --- |
| `candidate-start`、`probe-resources` | 候选依据、版本和资源规模 |
| `probe-result.matched` | 探测是否匹配 |
| `reuse-candidate.accepted` | 候选是否最终可用 |
| `discovery-phase`、`candidate-phase`、`analysis-phase`、`verification-phase` | 阶段状态及耗时 |
| `extraction-result.cached` | 是否复用已有提取结果 |

资源统计含数量、大小与有界路径样例，`complete=false` 表示统计不完整。阶段 `completed` 仅表示操作结束，是否通过需查看结果。大文件单独记录哈希和复制耗时；开始记录没有结束项时，还需核对任务状态，不能据此认定仍在运行。
