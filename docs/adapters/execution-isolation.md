# LLM 执行隔离

Windows 默认用 AppContainer 执行智能适配脚本、外部工具及生成适配器。复用这些适配器时也应用隔离设置。

## 能访问哪些文件

- 读取宿主本次授权的资源、适配器源码和运行依赖。Python 与发行版 VNTextPatch 可通过只读句柄访问游戏输入。
- 实验脚本和外部工具可写入工作区的 `work/`。生成的适配器可写入该次操作的指定输出和临时目录。脚本可以修改获准写入的文件。
- 隔离进程没有网络能力。宿主 API 密钥不随请求或环境传入。下载、发布与安装由宿主执行。

未接入只读句柄通道的工具可以通过标准输入接收资源数据。运行期间的子进程继承隔离限制，并随本次执行结束或取消而终止。[隔离工具源码](../../tools/GameL10n.ToolRunner)

## 补丁运行的风险

AppContainer 约束的是适配执行。游戏和启动器在宿主环境运行，补丁内的 EXE、DLL 和脚本可使用相应进程的权限。游戏资料和网络内容也可能影响生成结果，运行前需核对补丁来源和内容。资源验收只验证静态提取与回填，运行效果需实机确认。

## 设置与失败处理

隔离启动失败会停止该次执行并显示原因。缺少工具时恢复完整发行包，开发环境可用 `prepare-tools.ps1`。授权目录需支持 Windows 访问控制，输入路径须避开符号链接和目录联接。[工具准备](../development.md#工具准备)

当前 Windows 环境无法启动 AppContainer 时，在“程序设置”取消勾选“LLM 执行隔离”，点击“保存程序设置”后重试。关闭后，生成代码以当前用户权限运行。
