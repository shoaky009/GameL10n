# LLM 执行隔离

Windows 默认使用 AppContainer 执行智能适配中的 Python、PowerShell 和外部工具，以及 LLM 已生成的适配器。适配器之后的识别、提取、回填和验收也受隔离限制，即使当时没有调用模型。

## 能访问哪些文件

- 读取本次指定的游戏输入、适配器源码和固定运行依赖。
- 智能适配可写当前项目的 `adaptation/current`；适配器运行可写宿主指定的输出目录。
- 每次执行另有独立临时目录；容器也有 Windows 提供的私有存储。
- 不向进程提供宿主的 API 密钥等环境变量；保留互联网和局域网能力，仍受 Windows 防火墙与 AppContainer 的系统规则约束（包括本机回环访问）。

普通文件读写工具继续由宿主校验路径。联网检索、下载、发布和安装补丁由 Rust Host 执行，不进入 AppContainer。脚本启动的子进程继承隔离限制，并随执行结束或取消一起终止。

隔离限制工作目录外的访问，不保护同一工作目录内的文件免受脚本修改。Windows 仍允许容器访问部分系统运行资源；隔离也不能保证生成的代码或补丁正确。

## 补丁运行的风险

AppContainer 不会把隔离限制附加到生成的补丁文件上。补丁可能包含新增或修改的 EXE、DLL、脚本；在隔离外启动这些程序，或由游戏加载这些代码后，它们以相应进程的权限运行，恶意代码仍可能读取、修改或删除宿主文件，或通过网络泄露数据。当前机制不提供补丁恶意代码检测，也不隔离安装补丁后的游戏和启动器；资源验收、文件哈希校验和启动检查均不能证明补丁安全。

建议仅使用可信的 LLM 和服务接口，以降低生成恶意产物的风险。但可信模型的输出仍可能受游戏资源或外部资料中的提示词投毒影响，不能据此保证生成的补丁安全。

## 设置与失败处理

在“程序设置”中可关闭“隔离执行 LLM 脚本与生成适配器”，保存后用于后续启动的执行。关闭后，生成代码以当前用户权限运行，恶意指令或提示词投毒可能导致文件泄露、修改或删除。其他平台暂不支持该机制，默认关闭。

开启时若隔离启动失败，程序显示具体原因，不自动改用普通执行。可恢复完整发行包，或运行 `scripts/prepare-tools.ps1` 修复开发运行工具；目录授权失败时，使用支持 Windows 访问控制的本地目录，并确认当前用户可设置其权限。授权目录不支持符号链接或目录联接。也可以在了解风险后到程序设置关闭隔离，再重试。

隔离正常运行后，脚本越权读写被拒绝或工具进程异常退出属于工具失败。智能适配会记录错误并将结果返回模型，由模型调整后继续，不会因此结束整个任务或扩大访问权限。

## 实现位置

Windows API 集中在独立 Rust 工具 `tools/GameL10n.ToolRunner`，四个主 crate 通过 JSON 进程协议调用。宿主决定执行程序和读写目录，模型参数不能关闭隔离或扩大授权。每次执行使用独立 AppContainer 身份和进程 Job，正常结束后撤销目录授权并清理容器配置。
