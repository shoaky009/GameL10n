# 模型接口配置

> 完整产品的能力与协议参考；Rust 宿主的实际接入范围见[开发文档](development.md)。

在侧栏“全局 → API 与任务默认值”点击“新增 API 配置”，填写名称、协议、服务商地址、模型名称和 API Key。在同页选择默认分析 API、默认翻译 API 链，并保存默认适配 Token 预算和模型轮数。新项目直接使用这些默认值，无需逐个设置；“项目设置”中的管理按钮可直接跳转到此页。

## 按用途选择

| 用途 | 使用场景 |
| --- | --- |
| 智能识别与适配 | 调查引擎资源、检索工具、编写和验证解析及回填代码 |
| 文本翻译 | 对白、旁白、角色名和选项的批量翻译 |

第一份配置同时作为分析和翻译的全局默认。同一份配置可同时用于分析和翻译，也可以新增第二份配置，为分析选择编程模型、为翻译选择擅长语言的模型，两者的地址、协议和密钥均可不同。新增配置不会自动更改已有用途选择。已支持游戏的常规识别和资源提取不调用分析模型。

项目可分别选择分析 API、翻译 API 链、适配预算与轮数是否“使用全局默认”。勾选时显示当前默认值，修改全局默认后，项目的下一次任务立即使用新值；取消勾选后可独立设置，后续全局修改不会覆盖这些选择。API 选择、链顺序和跟随开关自动保存，独立预算修改后点击“保存项目设置”，也可在开始或继续适配弹窗中调整。语言、风格和术语仍单独保存在各项目中。

旧项目已有的 API 选择和适配预算保留为独立设置；如希望统一管理，在对应项目勾选“使用全局默认”即可。默认预算为 1M Token、60 轮，上限分别为 20M 和 400 轮，每次开始或继续适配重新计算本次用量，任一上限达到后暂停并保存进度。设置在重启后保留，运行中的任务继续使用启动时的 API、顺序和预算。

API 地址、模型和密钥仍是全局共享配置，编辑它们会影响所有引用该配置的项目的后续任务。删除配置后，独立引用它的项目显示“已删除的 API”，需重新选择或从链中移除；全局默认中的引用会移除，请检查剩余默认顺序。项目独立的空翻译链或已删除配置不会自动改用其他全局账号。旧版单个翻译 API 作为只有一项的翻译链继续使用。

## 分析思考等级

编辑 API 配置时可选择“分析思考等级”：接口默认、`low`、`medium`、`high` 或 `xhigh`。默认不发送此参数，具体支持范围由模型和接入服务决定；不支持时应改回接口默认或选择服务支持的等级。此选项仅用于智能识别与适配，不改变文本翻译请求。

复杂的资源分析可以先尝试 `high`。更高等级允许模型投入更多推理，可能增加单次请求时间和 Token 消耗，不保证整个适配任务更快。Responses 发送 `reasoning.effort`，Chat Completions 发送 `reasoning_effort`，参见 [OpenAI 推理指南](https://developers.openai.com/api/docs/guides/reasoning)。调整等级后开始或继续任务即可生效；已有源码、会话和翻译缓存继续使用。

## 文本翻译 API 链

### 本地专用翻译模型

GalTransl 等专用翻译模型可能会把整个 JSON 请求当作原文翻译。编辑该 API 配置，将“翻译输入格式”设为“逐条纯文本”。例如 llama.cpp：协议选择 Chat Completions，地址填写 `http://localhost:8080/v1`，模型填写服务提供的名称，无鉴权时 API Key 可留空。

逐条模式的 user 消息只有一条原文；翻译目标、项目翻译风格及原文中出现的术语放在 system 中。模型无需返回 JSON 或文本 ID，也不会收到资源路径、相邻对白或其他上下文。游戏标记仍由程序替换为简单占位符并在返回后恢复、校验。此模式减少格式负担，但翻译质量和语言支持仍取决于模型。

每条译文通过校验后立即保存，中断后继续未完成的文本。翻译链中包含逐条模式时，整条链按单条提交，以保证切换 API 时文本对应且已完成结果可恢复；批量 JSON 模式的旧配置保持原行为。切换格式不会清空已保存译文。Chat Completions 的逐条模式使用 `max_tokens` 和 `temperature: 0.2`；不改变智能识别的请求方式。纯文本译文中的拒绝式对白不会被当作模型拒绝，只有 API 的明确 refusal 或内容过滤状态触发切换。

本地服务的运行上下文长度应容纳提示词、原文和译文；模型标称支持的长度不等于服务实际配置。普通对白可先试译少量文本；长段文本或较长术语、风格提示可能需要增大服务的上下文配置。

### 链顺序与重试

在“文本翻译 API 链”下方选择已保存的配置，点击“添加到链末尾”。选中链中一项后，可用“上移”“下移”调整优先级，或“从链中移除”。新增 API 配置不会自动加入已有翻译链。

每批文本从链首开始：当前模型明确拒绝或表示无法处理内容时，把同一批文本、上下文和翻译规则交给下一项；任一 API 成功后停止向后调用。新的批次仍从链首开始。链中所有 API 均拒绝时暂停任务，保留已完成译文。任务日志显示当前 API 的序号、切换及重试进度。

网络异常、HTTP 429、超时、身份验证或其他 HTTP 错误、输出截断和格式错误均不触发切换。这些错误只对当前 API 使用原有重试策略，耗尽后暂停。翻译链可包含不同服务商、模型及协议。

勾选“记住 API Key”时，密钥使用 Windows 当前用户的数据保护功能加密保存，设置文件不包含明文密钥。将设置迁移到另一台电脑或另一位 Windows 用户时，需要重新填写密钥。取消勾选则仅在本次运行中使用，重启后需要重新填写密钥，其他配置和用途选择仍保留。编辑时清空 API Key 可移除该配置的已保存密钥。

## 接口地址

| 协议 | 基础地址示例 | 完整地址示例 |
| --- | --- | --- |
| Chat Completions | `https://api.openai.com/v1` | `https://api.openai.com/v1/chat/completions` |
| OpenAI Responses | `https://api.openai.com/v1` | `https://api.openai.com/v1/responses` |

使用其他服务商时替换地址并填写其支持的模型。完整接口地址必须与所选协议对应。应用不会在失败后自动切换协议，以避免重复请求。

## 协议行为

Chat Completions 使用 `messages`；批量 JSON 模式发送 `max_completion_tokens`，逐条纯文本模式发送 `max_tokens`。Responses 使用 `instructions`、`input` 和 `max_output_tokens`，以 `store: false` 请求不保存供后续 API 检索的响应；这不等于服务商承诺零保留。两种协议均使用非流式响应。

Responses 从 `output` 中的助手消息读取 `output_text`，跳过推理项。未完成、拒绝或格式不正确的响应不会提交到翻译缓存。应用不为翻译请求启用工具调用或多轮会话。

智能适配使用多轮函数工具调用，模型及接入服务必须支持所选协议的工具请求。每次工具执行结果交回同一会话；Responses 保留后续调用所需的输出项及加密推理内容，Chat Completions 保留助手消息及工具调用 ID。当前会话保存于项目开发目录，用于继续任务，不另存每轮成功请求和响应文件。协议约定见 [OpenAI Docs：Function calling](https://developers.openai.com/api/docs/guides/function-calling)。

Token 统计优先采用服务商返回的用量；缺少用量时标记为估算。Responses 的输出 Token 已包含服务商统计的推理消耗，不重复累加。失败响应中返回的用量也会计入统计。

两种协议的翻译请求遇到 HTTP 错误、网络中断和无效响应时，对当前 API 自动重试 5 次，每次等待 10 秒，不会因此转交链中的下一项。仍失败则暂停任务，继续全量翻译或重新提交相同试译选区只处理未完成的文本。游戏分析沿用独立的重试策略。

模型明确拒绝处理内容时不对该 API 重试，而是立即尝试翻译链中的下一项；没有下一项时暂停。除协议的 `refusal` 字段和内容过滤状态外，也识别普通正文及单独的 `error` / `refusal` JSON 对象中的明确拒绝说明；正常译文中的“我不能”等对白不参与拒绝判断。拒绝记录保存在游戏任务的 `responses/*.refusal.json`，绑定该批次的模型接口、文本、上下文和翻译规则。重新开始相同批次会跳过已拒绝的 API，继续尝试后续配置；所有配置均有拒绝记录时直接暂停，不再产生 API 调用。调整翻译链或追加配置后可以继续尝试，原拒绝记录仍保留。旧版误记为 JSON 格式错误的明确拒绝也会从已有日志中识别。拒绝响应不会写入译文缓存，后续 API 成功返回的译文正常保存，并记录实际提供译文的 API；其他已完成译文继续保留。拒绝说明不能当作译文或成功结果使用。所有已发出请求返回的 Token 用量均计入本次任务，读取旧拒绝记录不重复计费或累计用量。

拒绝响应可能不符合正常输出的 JSON 结构，参见 [OpenAI Docs：拒绝响应](https://developers.openai.com/api/docs/guides/structured-outputs#refusals-with-structured-outputs)。

批量 JSON 模式的翻译结果接受纯 JSON 或完整的 JSON 代码块，仍须包含全部请求 ID，且不能包含未知 ID、重复 ID 或非字符串译文。逐条纯文本模式直接读取译文，由程序关联原文本 ID。截断的响应不会作为完整译文提交。

程序在请求前将控制标记、富文本标签、动态数值和可翻译强调文字的括号换成简单编号占位符，返回后恢复原格式。模型只需翻译可见文字并保留编号；较长的文本 ID 使用请求内短编号，保存译文前还原。原始游戏格式、缓存 ID 和校对记录不受影响，两种协议均使用此处理。若编号丢失、重复或来自其他条目，仍按原文执行校验，不会猜测补齐。已有校验反馈也会转换成当前请求的编号。

每个文本条目独立翻译，即使几条看起来可以拼成完整句子，也不能跨 ID 搬移词句或数值。片段可以保持不完整；资源中的拼接方式由适配器处理。此约束可减少模型需要处理的格式复杂度，但不能保证模型永远不漏译。

界面显示简短的失败原因和重试进度，例如网络异常、请求超时、限流或额度限制、身份验证失败、返回格式不正确、文本 ID 重复或输出被截断。重试耗尽后也会保留最后一次失败原因。开发诊断写入当前游戏数据目录的 `logs/api-*.json`，包含协议、模型、用量、错误分类及翻译响应片段；不记录请求头、API Key 或独立的推理字段。片段最多保留开头和结尾各 8,192 个字符，可能包含剧情译文。通过“打开日志目录”可直接查看。JSON 语法错误、ID 不匹配和输出达到 Token 上限在日志中分别标记，便于定位服务商兼容问题。

接口定义：[OpenAI Responses](https://developers.openai.com/api/reference/resources/responses/methods/create)、[Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。
