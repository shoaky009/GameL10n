# 模型接口配置

在“全局 → API 与任务默认值”新增配置，填写名称、协议、地址、模型和 API Key，再选择默认分析 API、翻译链和适配预算。

## 按用途选择

| 用途 | 要求 |
| --- | --- |
| 智能识别与适配 | 支持函数工具调用，用于资源调查、代码开发和验证 |
| 文本翻译 | 翻译提取出的游戏文本，可使用专用本地模型 |

同一配置可用于两种用途，也可分别选择服务。第一份配置自动作为两者默认，新增配置不改变已有选择。常规识别不调用分析模型。

项目未配置的选项跟随全局；修改后仅该项使用项目值。API 选择和链顺序自动保存，预算和轮数在保存设置或关闭适配配置时保存。运行中的任务使用启动时的配置。

适配默认预算为 1M Token、60 轮，上限为 20M 和 400 轮。每次开始或继续任务重新计算本次用量，达到任一上限后保存进度并暂停。语言、风格和术语按项目保存。

编辑 API 地址、模型或密钥会影响所有引用它的项目的后续任务。项目引用的 API 被删除时须重新选择；项目独立的空翻译链不会回退到全局账号。

勾选“记住 API Key”后，密钥由 Windows 当前用户加密保存，换用户或电脑需重新填写；不勾选则只在本次运行中使用，清空密钥可移除已保存值。

## 分析思考等级

可选接口默认、`low`、`medium`、`high` 或 `xhigh`，仅用于智能适配。接口默认不发送该参数，支持范围由服务商决定；更高等级可能增加耗时和 Token 消耗。

Responses 发送 `reasoning.effort`，Chat Completions 发送 `reasoning_effort`。调整后开始或继续任务生效。

## 文本翻译 API 链

### 本地专用翻译模型

普通模型使用“批量 JSON”，按项目的每批文本数提交。只接受原文的专用模型可选“逐条纯文本”，例如 llama.cpp：

| 设置 | 示例 |
| --- | --- |
| 协议 | Chat Completions |
| 地址 | `http://localhost:8080/v1` |
| 模型 | 服务提供的名称 |
| API Key | 无鉴权时留空 |

逐条模式的 user 消息只包含一条原文，翻译目标、风格和相关术语放入 system，不要求 JSON 或文本 ID。该模式不提供资源路径和相邻文本；服务的上下文长度须容纳提示词、原文和译文。

后备逐条接口只在轮到它时拆分当前批次，不影响前面接口的批量大小，也不重新调用已拒绝的接口。每条有效译文立即保存。

### 链顺序与重试

将已保存配置添加到链中，用上移、下移调整顺序。每批从链首开始，当前 API 明确拒绝内容时才交给下一项；成功后停止，下一批仍从链首开始。

网络、超时、HTTP 错误、限流、截断和格式错误不切换 API，对当前接口最多重试 5 次。返回格式错误时立即重试，其他错误每次等待 10 秒。重试耗尽或整条链拒绝时，记录该批失败并继续后续批次。

拒绝记录绑定 API、文本、上下文和翻译规则。相同请求再次执行时跳过已有拒绝记录的接口；可调整链或追加配置继续。拒绝说明不会作为译文保存，普通对白中的拒绝语句不据此判为模型拒绝。

## 批次失败与继续

全量、所选、重新翻译和试译共用以下规则：

- 有效译文提交后可复用，失败条目可通过“翻译失败”筛选重试。
- 重译失败保留旧有效译文，同时记录本次失败。
- 试译有失败时不自动生成补丁；补丁构建失败后继续会复用已保存译文和原选区。
- 取消、文件读写或提交错误停止任务。

## 接口地址

| 协议 | 基础地址 | 完整地址 |
| --- | --- | --- |
| Chat Completions | `https://api.openai.com/v1` | `https://api.openai.com/v1/chat/completions` |
| OpenAI Responses | `https://api.openai.com/v1` | `https://api.openai.com/v1/responses` |

其他服务替换地址和模型即可。完整地址须与协议对应，失败时不自动切换协议。

## 协议行为

两种协议均使用非流式响应。

| 项目 | Chat Completions | Responses |
| --- | --- | --- |
| 输入 | `messages` | `instructions`、`input` |
| 输出限制 | 批量 `max_completion_tokens`；逐条 `max_tokens` | `max_output_tokens` |
| 译文读取 | 助手消息 | 助手消息中的 `output_text`，跳过推理项 |

逐条 Chat 模式使用 `temperature: 0.2`。Responses 使用 `store: false`，但服务商的数据保留政策仍以其约定为准。

批量结果接受 JSON 或完整 JSON 代码块，须包含全部请求 ID，不得包含未知、重复 ID 或非字符串译文。逐条模式由程序关联 ID。截断或无效结果不会作为完整译文提交。

请求前将控制标记、富文本标签、动态数值和格式括号替换为编号占位符，响应后恢复并校验；请求内短 ID 会还原为原 ID。编号丢失、重复或串项时拒绝对应结果，不猜测补齐。各条文本独立翻译，不跨 ID 搬移词句。

智能适配使用多轮工具会话；Responses 保留后续调用需要的输出项与加密推理内容，Chat Completions 保留助手消息和工具调用 ID。翻译请求不启用工具会话。

Token 优先使用接口返回值，缺失时标记估算；推理消耗不重复累加，失败请求返回的用量也计入统计。

界面显示网络、限流、鉴权、格式或截断等简要错误。开发诊断保存在项目 `logs/api-*.json`，包含协议、模型、用量、错误分类和有限响应片段，不记录密钥或独立推理字段；片段可能包含游戏文本。
