# 模型接口配置

在左侧“模型配置”填写协议、地址、模型名和 API Key，再选择默认分析 API 与翻译链。可用“测试翻译”或“测试分析”检查正在编辑的配置。测试发送固定样例，按服务商规则计费。

| 用途 | 如何选择 |
| --- | --- |
| 智能适配 | 支持函数工具调用的模型。用于调查未知格式、开发适配器和修复。 |
| 文本翻译 | 支持批量 JSON 的模型，或支持逐条纯文本的专用翻译模型。 |

## 按用途选择

项目设置可分别覆盖全局的分析接口、翻译链和预算。项目独立设置为空翻译链时，需为该项目选择接口。修改共享 API 配置会影响引用它的项目下一次运行。

“记住 API Key”使用 Windows 当前用户加密保存密钥。换电脑或 Windows 用户后需重新填写。取消记住时，密钥仅用于当前程序会话。

每个 API 配置可设置“最大并行请求数”（1–16），跨所有项目全局共享上限，调高后同一项目也可并行发送多个翻译批次；“程序设置”另可控制允许并行执行翻译任务的最大项目数（1–8）。

收到 HTTP 429 后，同一服务地址和 API Key 的翻译、分析和连接测试会共享冷却时间。优先按服务商的 `Retry-After` 等待，最长 30 秒。缺少有效等待时间时，首次限流默认等待 1 秒。

### 接口地址

| 协议 | 基础地址 | 完整地址 |
| --- | --- | --- |
| Chat Completions | `https://api.openai.com/v1` | `https://api.openai.com/v1/chat/completions` |
| Responses | `https://api.openai.com/v1` | `https://api.openai.com/v1/responses` |

其他兼容服务填写其地址和模型名。完整地址须与所选协议对应。

### 本地专用翻译

例如使用 llama.cpp 时可选 Chat Completions，地址填 `http://localhost:8080/v1`，模型填服务端提供的名称。服务无鉴权时可留空 API Key。

只接受原文的模型选“逐条纯文本”，每次发送一条原文和翻译规则。需要批量翻译及上下文时使用“批量 JSON”。

## 智能适配预算

智能适配和引擎总结分别按每次运行累计输入与输出 Token。适配预算不足时暂停并保存进度，继续时按本次设置重新计量。思考等级与单次输出上限仅用于分析模型，按服务商支持范围设置。提高思考等级可能增加耗时和消耗。[适配暂停与继续](adapters/automatic-adaptation.md#进度与继续)

引擎总结先使用宿主整理的验收结果、发布清单和相关证据入口。较长的历史工具结果在后续请求中保留预览和回查编号，原始片段可按需读取。

智能适配和引擎总结均使用流式分析。收到 HTTP 429 或 5xx 时，会在同一接口最多重试两次。总结收到 HTTP 408，或在服务商返回用量前发生首字节或流式空闲超时，也会在本轮重试。等待优先采用服务商返回的 `Retry-After`，最长 30 秒，期间可以取消。重试用尽后报告最后一次请求的错误。

智能适配遇到连接或响应体读取失败、HTTP 408、超时、缺少流终止事件、响应或工具调用格式错误时，在本次 Token 预算内重试当前轮次，合计最多两次。收到完整有效的响应后才执行工具。服务商已报告的失败用量计入预算。任务日志列出重试次数和具体原因，传输错误保留失败阶段和可用的底层错误，流读取失败还会记录已收到的字节数。

## 文本翻译 API 链

每批从链首开始。整批拒译或批量 JSON 响应格式无效时，整批直接转到下一接口。批量 JSON 也支持逐条返回 `null`，同批有效译文照常保存，只有拒译条目转到下一接口。链用尽后，未完成条目列入“翻译失败”。

网络故障、限流和 HTTP 5xx 在当前接口重试。续译时会参考已知拒译记录。

## 批次失败与继续

- 成功的译文可以继续使用。任务有失败条目时标记失败，通过“翻译失败”筛选重试。重译失败保留旧有效译文。
- 试译须完成整个选区才生成补丁。补丁构建失败后继续会复用已保存译文和原选区。
- 上次请求结果未知时，接口可能已处理或计费。确认后可重试待处理项。

使用远程接口时，选中的文本和相关翻译上下文会发送给服务商。项目日志中的 API 故障诊断可能包含文本片段，分享前请检查。[适配诊断](adapters/automatic-adaptation.md#诊断)
